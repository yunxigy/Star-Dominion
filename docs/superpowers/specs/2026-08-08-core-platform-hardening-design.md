# 核心平台收敛与可靠性加固设计

日期：2026-08-08

## 目标

在不改变现有业务功能、登录态和同花顺数据源的前提下，收敛三类横切逻辑：本地服务编排、站点认证契约和 SQLite schema 迁移。完成后，启动/停止/健康检查有单一事实来源，跨服务认证行为一致，新旧数据库都能通过显式、幂等的迁移入口升级。

## 范围与非目标

范围只覆盖 `scripts/`、`site-auth`、`research-reports`、股票后端认证适配器和守岸人数据库初始化。不会合并业务数据库，不会替换同花顺依赖，不会删除仍被入口或测试引用的旧脚本，也不会修改 OpenWrite、前端页面或 AI 业务算法。

## 方案

### 1. 运行编排

新增 `scripts/local-services.json` 作为服务清单，记录服务名、工作目录、可执行文件、参数、端口和健康检查 URL。`start-local.ps1`、`stop-local.ps1`、`check-local.ps1` 共享读取器；启动脚本继续支持 `-WithoutFrontends`，但不再复制端口定义。运行时元数据增加命令摘要和健康 URL，停止时校验 PID、启动时间、工作目录和命令摘要，避免 PID 被系统进程复用。健康检查覆盖 8000–8009 与 5173–5175，并区分 TCP 端口和 HTTP 健康状态。

清单只描述本地开发编排，不把秘密写入仓库；环境变量仍由 `.env.local` 提供。JSON 解析失败、目录不存在、端口冲突和健康超时都输出可定位的服务名与文件路径。

### 2. 认证契约

新增轻量的跨服务契约模块（不引入共享运行时包），集中定义：会话 Cookie `sd_session`、CSRF Cookie `sd_csrf`、转发头 `X-Site-Request-Origin`/`X-Site-CSRF`、浏览器头 `Origin`/`X-CSRF-Token`、以及 401/403 的语义。`research-reports` 与股票后端的 HTTP 客户端改为使用同一组常量和构造函数；守岸人保留自身依赖注入方式，只替换重复字符串和错误映射。兼容现有前端，不改变 cookie 名称、接口路径或认证服务地址。

适配器负责请求头/cookie 拼装和 `httpx` 错误映射，业务路由只关心“未登录”“无权限”“请求失败”三种结果。所有适配器都有单元测试覆盖：带 cookie+CSRF、无 CSRF、非 2xx 响应和网络异常。

### 3. SQLite 迁移

每个服务继续独立数据库。新增一个小型迁移运行器：维护 `schema_metadata` 表（单行版本号），按递增版本执行幂等函数，并在事务内更新版本。`create_all` 只用于空库；已有库先执行迁移，再创建缺失表。研究报告现有 `ai_reports` 两个增量字段迁移改为版本 1；守岸人现有 `_ensure_column`、聊天图迁移保留行为但收拢到版本化步骤，旧数据一次性迁移后不会重复扫描。站点认证当前无增量变更，仍通过 `create_all` 初始化并预留版本表。

迁移失败必须回滚并抛出带版本号的异常；启动服务不吞掉迁移错误。迁移测试使用临时 SQLite：空库初始化、旧 schema 升级、重复执行不产生重复列/索引、失败回滚。

## 兼容与回滚

所有改动保持现有入口和环境变量不变。服务清单缺失时脚本立即失败并提示修复文件；迁移器保留原函数名包装器一段时间，旧测试和外部脚本仍可调用。若升级失败，可停止服务并使用升级前数据库备份；代码回滚不会删除新增列。

## 验证

按阶段执行：脚本 JSON/PowerShell 语法检查与本地 smoke；认证适配器专项测试；三个服务的完整 pytest；前端构建不因后端改动受影响。最终运行 `scripts/check-local.ps1`，记录端口、健康端点、匿名 401、管理员登录和跨服务认证结果。
