# 守岸人 3.0 资源权限与世界书一致性设计

日期：2026-08-09

## 目标

本阶段修复守岸人 3.0 中已经确认的资源越权和世界书字段不一致问题，建立一条可复用的资源归属校验路径，并为故事、世界书、旧版角色和亲密度入口补齐回归测试。

完成后应满足：

- 未登录用户不能读取剧情会话详情或消息。
- 登录用户不能读取、修改或删除其他用户的私人资源。
- 世界书的读写权限从关联角色的可读、可编辑规则派生，不再只凭资源 ID 操作。
- 旧版 JSON 角色仍可读取，但只有管理员能够修改文件型角色资源。
- 亲密度人工加分入口只允许管理员调用，普通聊天增长仍通过内部函数完成。
- `LorebookEntry.priority` 在模型、数据库迁移、接口和聊天排序中保持一致。

## 不在本阶段处理

- 不重写前端框架。
- 不把同步 LLM 调用改为异步。
- 不实现世界书概率、冷却、分组和递归触发等完整求值引擎。
- 不迁移或删除现有 JSON 角色文件。
- 不改变统一站点账号、Cookie 和 CSRF 认证方式。

完整世界书求值、对话回合编排和异步流式输出分别作为后续阶段处理。

## 方案比较

### 方案 A：在每个 Router 中直接补条件

改动最少，但相同的角色可读、角色可编辑、会话归属规则会继续复制。之后新增入口时仍容易漏掉校验，Locality 较差。

### 方案 B：建立资源访问 Module（采用）

在 `server/services/resource_access.py` 集中实现资源查找和归属校验。Router 只取得“已校验资源”，然后执行自身业务。该 Module 的 Interface 小，能够隐藏查询、公开资源、管理员和旧版文件资源的差异。

### 方案 C：引入通用 RBAC/策略框架

扩展性最高，但当前只有管理员、普通用户和资源所有者三类规则。引入策略语言或第三方权限框架会增加配置和调试成本，本阶段不采用。

## 资源访问规则

### 角色

- 管理员可读、可编辑全部数据库角色。
- 普通用户可读取自己创建、自己绑定或公开的数据库角色。
- 普通用户只能编辑自己创建或自己绑定的数据库角色。
- 旧版 JSON 角色可被登录用户读取，但只有管理员能修改、上传关联资源或删除。
- 不存在或当前用户无权访问的私人资源统一返回 `404`，避免通过状态码枚举资源。

### 剧情会话

- `/api/stories/sessions/{session_id}` 必须登录，并要求 `StorySession.user_id` 等于当前用户 ID。
- `/api/stories/sessions/{session_id}/messages` 先取得已归属的会话，再查询消息；不存在或不归属均返回 `404`。
- 已有分支、发送消息和删除会话入口改为复用同一资源访问 Module，消除不同端点间的错误语义差异。

### 世界书

- 读取角色世界书前，必须取得一个当前用户可读的角色。
- 创建、修改、删除世界书或条目前，必须取得一个当前用户可编辑的关联角色。
- 条目操作从条目关联到世界书，再关联到角色进行校验，不能仅按条目 ID 修改。
- 世界书仍属于角色，不在本阶段新增独立 `owner_id`；这与现有聊天按 `character_id` 注入世界书的语义一致。

### 亲密度

- `/api/affinity/characters/{character_id}/add-points` 改为管理员入口。
- `points` 限制为正整数且设置合理上限，拒绝负数和无限放大。
- 普通聊天继续调用内部 `update_affinity_on_chat`，不经过管理员 HTTP 入口。

## 世界书字段一致性

`LorebookEntry` 增加持久化字段 `priority: Integer = 0`，含义是不同触发条目之间的优先级；现有 `order` 保留，含义是相同注入位置内的稳定顺序。两者不再混用。

数据库版本从 1 升至 2。版本 2 迁移使用现有幂等列迁移能力为 `lorebook_entries` 添加 `priority`，已有数据库默认值为 0；新数据库由 SQLAlchemy 模型直接创建完整字段。

接口输入增加约束：

- `selective_logic` 只能是 `and` 或 `or`。
- `position` 只能是 `before_char`、`after_char` 或 `depth`。
- `probability` 必须位于 0 到 1。
- `cooldown`、`depth` 不得为负数。

本阶段只保证这些字段能够安全读写和排序。完整触发行为在下一阶段的世界书求值 Module 中实现。

## 错误与事务

- 资源缺失或无权访问：`404`。
- 未登录或会话失效：由统一认证返回 `401`。
- 普通用户调用管理员亲密度入口：`403`。
- 输入字段越界：Pydantic 返回 `422`。
- 写操作在单个数据库事务中完成；校验失败前不产生写入。

## 测试设计

测试遵循先失败、再实现：

1. 匿名读取故事会话详情和消息返回 `401`。
2. 用户 A 读取用户 B 的故事会话与消息返回 `404`。
3. 用户 A 不能修改用户 B 角色关联的世界书或条目。
4. 公开角色的世界书可读，但非创建者不能修改。
5. 普通用户不能删除旧版 JSON 角色；管理员可以。
6. 普通用户调用亲密度加分返回 `403`，非法分值返回 `422`。
7. 新数据库和从版本 1 升级的数据库均存在 `lorebook_entries.priority`。
8. 世界书创建、排序和序列化均使用持久化的 `priority`。
9. 守岸人现有全量测试、内嵌 JavaScript 语法检查和全站冒烟检查继续通过。

## 实施顺序

1. 为故事会话越权、世界书越权、旧版角色写入和亲密度入口增加失败测试。
2. 添加资源访问 Module，并让相关 Router 复用。
3. 增加 `priority` 模型字段和版本 2 迁移，补迁移测试。
4. 增加世界书输入约束与接口测试。
5. 运行守岸人全量测试、语法检查，重启服务并执行全站冒烟检查。

## 风险控制

- 不删除现有数据和 JSON 文件。
- 不改变公开角色的读取行为。
- 数据库迁移为幂等加列，可重复执行。
- 所有改动限定在守岸人及对应设计、测试文件，不暂存或覆盖工作区中的其他模块改动。
