# 塔罗 78 张暗金 WebP 重绘设计

日期：2026-08-09
状态：设计已确认，待书面复核

## 目标

基于 `SD/components/tools/tarot/tarot_78_dark_gold_prompts.md` 重绘主站塔罗模块使用的完整 78 张牌，并将前端默认牌面从现有 SVG 切换为 1024×1536 WebP。整套牌保持统一的暗金神秘风，同时让每张牌的核心象征和四种小阿卡纳花色易于辨识。

## 范围

本次包含：

- 22 张大阿卡纳；
- 圣杯、金币、宝剑、权杖各 14 张；
- 3 张先行样牌：愚者、死神、圣杯 A；
- WebP 资源接入、中英文牌名叠层和 SVG 回退；
- 资源完整性检查、视觉质检、前端构建和映射测试。

本次不包含：

- 重绘牌背；
- 为正位和逆位分别生成图片；
- 删除或覆盖现有 SVG；
- 修改塔罗牌义、抽牌概率或占卜逻辑。

## 已确认决策

1. 最终格式使用 WebP，不继续把 AI 插画作为 SVG 交付。
2. 采用分批方案：先确认 3 张样牌，再依次生成大阿卡纳、圣杯、金币、宝剑和权杖。
3. 每张图片只包含插画和极细暗金装饰边框，不包含可读文字。
4. 罗马数字或序号、中文牌名、英文牌名由前端统一叠加。
5. 现有 SVG 保留为回退资源。
6. 牌背保持现状。

## 视觉规范

所有牌面采用 1024×1536、2:3 竖版构图。最终文件使用 sRGB、WebP quality 90，并移除不必要的图片元数据。主体位于中央或中央略偏下，上方保留牌号空间，下方保留中英文牌名空间。画面使用黑曜石黑、古旧暗金、午夜蓝、深酒红和墨绿；金色必须是低饱和的 aged gold 或 antique gold，不使用亮黄色或高亮“土豪金”。

画面可以使用月相、星盘、炼金术几何、黑色石柱、祭坛、烛火、薄雾和古老纹样，但不得出现现代物件、霓虹、赛博朋克、动漫大眼、Q 版、Logo、水印或可读文字。每张牌至少保留一个远看即可辨认的经典核心符号。

四组小阿卡纳使用不同环境语言：

| 花色 | 主环境 | 辅助颜色 | 核心材质 |
|---|---|---|---|
| 圣杯 | 湖面、海岸、月夜、薄雾 | 午夜蓝、银白 | 暗金圣杯、月光石、水 |
| 金币 | 庄园、田野、城市、工坊 | 墨绿、深棕 | 暗金币、石材、天鹅绒 |
| 宝剑 | 高空、海岸、风暴、冷色建筑 | 银灰、冷蓝 | 银黑长剑、冷金、铁 |
| 权杖 | 荒原、山地、火焰、城堡 | 深红、暖棕 | 古木权杖、暗金火星 |

## 提示词与生成流程

每张牌独立调用图像生成，最终提示词按以下顺序拼接：

1. 提示词文件中的统一前缀；
2. 对应牌的专属画面 Prompt；
3. 统一后缀；
4. 统一 Negative Prompt。

第一阶段只生成愚者、死神和圣杯 A。三张样牌分别验证人物主体、复杂叙事、多角色与器物主体，重点检查人物风格、暗金色、边框、暗部密度、核心符号和整体收藏卡质感。样牌获得用户确认后才生成剩余 75 张。

正式批次顺序如下：

1. 大阿卡纳；
2. 圣杯；
3. 金币；
4. 宝剑；
5. 权杖。

每批完成质检后再进入下一批。单张不合格时只重绘该牌，不重新生成已通过的牌面。

## 文件组织与命名

最终 WebP 保存到 `SD/public/assets/tarot/cards/`。为减少前端映射改动，新文件沿用现有 SVG 的文件主体名，仅替换扩展名：

- `tarot_00_fool.webp`
- `tarot_21_world.webp`
- `tarot_cups_ace.webp`
- `tarot_pentacles_king.webp`
- `tarot_swords_king.webp`
- `tarot_wands_king.webp`

现有同名 SVG 保留。最终目录包含 78 个 WebP 正面资源、78 个 SVG 回退资源和现有 `tarot_back.svg`。

## 前端接入

`tarot-data.ts` 作为牌面元数据的唯一来源，维护编号、中文名、英文名、花色和图片标识。`TarotCardVisual` 默认加载 WebP；WebP 缺失、损坏或加载失败时切换到同名 SVG。

前端叠层包含：

- 顶部罗马数字或小阿卡纳序号；
- 底部中文牌名；
- 中文牌名下方的英文牌名。

文字叠层使用固定暗金排版、渐变遮罩和安全边距，保证在不同明暗背景上可读。正逆位继续共用同一资源；本次在 `TarotCardVisual` 中补齐逆位图片旋转 180° 的实现，同时保留逆位状态标识，不生成第二套图片。

在 78 张 WebP 全部通过质检前，前端不得切换默认资源。

## 质量控制

自动检查必须验证：

- WebP 文件数恰好为 78；
- 每个文件都能解码；
- 每张尺寸为 1024×1536；
- 文件名与 78 张牌元数据一一对应；
- 前端引用不存在缺失资源；
- SVG 回退路径仍然有效。

人工视觉检查必须验证：

- 人物脸部和绘画质感属于同一套牌；
- 暗金色、边框、暗部密度和高光强度一致；
- 没有现代物件、乱码、Logo、水印和无意义字符；
- 没有明显畸形肢体、多余手指或重复人物；
- 数字牌中的圣杯、金币、宝剑或权杖数量正确；
- 大阿卡纳保留提示词指定的经典核心象征；
- 不同牌面的背景和构图具有足够差异。

## 测试与验收

实现完成后运行：

1. 资源清单与图片尺寸检查；
2. 塔罗资源映射测试；
3. 前端单元测试；
4. 前端生产构建；
5. 每日塔罗、三牌阵、爱情塔罗、事业塔罗和是/否塔罗的浏览器抽牌检查；
6. 正位、逆位、放大预览和 SVG 回退检查。

验收完成的定义：78 张 WebP 全部存在并通过自动检查，五种抽牌模式默认显示新牌面，中英文牌名叠层正确，逆位与预览正常，任一 WebP 加载失败时能显示原 SVG，并且前端测试和生产构建通过。

## 回退方案

旧 SVG 全程保留。若新牌面出现资源或兼容性问题，可将默认扩展名切回 `.svg`，无需恢复被覆盖文件。未完成或未通过质检的 WebP 不进入前端默认路径。
