# 小市值倍量吸筹选股策略设计

## 状态

已获用户确认，进入实现前设计审阅阶段。

## 目标

在股票研究模块中增加一套独立的“小市值倍量吸筹”候选策略：

- 扫描全部沪深 A 股主板，不限制在当前热门概念池。
- 使用当次行情采集得到的总市值，筛选总市值严格低于 100 亿元的股票。
- 识别最近三个交易日内的首次明显放量信号。
- 与现有的 2B、首板沿 5 日线、龙头识别策略完全隔离。
- 在 API 候选结果和前端工作台中作为独立来源、独立一列展示。

这套规则只是用低波动和量能变化近似“可能开始吸筹”的形态，不宣称能够证明股票不存在庄家或操纵行为。

## 已确认的规则

对每只股票，在其最近一个交易日可用的日线序列上执行：

1. 股票必须是沪深 A 股主板，排除 ST、退市和其他板块。
2. 当次全市场行情中的总市值 `< 10,000,000,000` 元。
3. 倍量日定义为：当日成交量 `>=` 前 5 个交易日平均成交量的 2 倍；前 5 日平均成交量必须大于 0。
4. 只检查最近三个交易日，三个交易日按时间顺序而非自然日计算。
5. 候选信号日前的连续 30 个交易日中，不得出现按同一公式计算的其他倍量日。判断这些日期的倍量时，允许使用它们之前的 5 个交易日作为基准。
6. 同一个信号日前的 30 个交易日内，收盘价最高值与最低值的区间相对最低值不超过 25%。
7. 同一窗口内按时间顺序计算的收盘价最大回撤不超过 15%。
8. 最近三个交易日中有多个符合条件的日期时，取最早的符合日期，并在候选卡片上标记“首日倍量”。
9. 不额外要求信号日涨跌方向、涨停状态或新闻题材；避免在已确认规则之外引入隐含过滤条件。

稳定性窗口不包含信号日，目的是衡量放量前的盘整状态。Worker 继续获取至少 150 个交易日，避免边界数据不足；策略本身最低只依赖 30 日窗口、5 日基准和最近 3 日信号范围。

## 架构方案

采用“同一 Worker、独立快照字段、独立候选来源”的方案。

### Worker 与快照

现有 `workers.user_strategy_snapshot` 仍是唯一的用户策略刷新 Worker，但输出分成两块：

- `stocks`：保留现有热门概念池及 2B、首板沿 5 日线、龙头识别策略。
- `small_cap_stocks`：由一次全市场行情采集筛出的全部主板小市值股票及其历史日线，专供新策略使用。

全市场行情优先使用 AKShare 的东方财富行情接口，读取“总市值”字段。无法得到有效总市值的股票直接跳过；总市值接口失败时，新策略来源报告错误或沿用上一份有效快照，不能用没有市值字段的数据冒充符合条件。现有用户策略和九点猫研来源不因新策略失败而停止。

日线快照增加交易日期字段，保留现有价格、涨跌幅和成交量字段。旧的 `stocks` 快照仍可被现有读取器消费；缺少 `small_cap_stocks` 或日期字段的旧快照不能生成新的有效候选。

### 领域与候选来源

在策略领域层增加一个纯函数，输入小市值股票的总市值和日线序列，输出是否命中、触发日期、倍量倍数、价格区间、最大回撤和可读原因。该函数不负责网络访问和文件写入，便于边界测试。

新增 `small_cap_absorption` 候选来源读取同一份 Worker 快照的 `small_cap_stocks`，将命中结果转换为独立的 `CandidateBatch`：

- `source_id = "small_cap_absorption"`
- `source_name = "小市值倍量吸筹"`
- 不使用与现有策略可横向比较的虚构分数，分数为空。
- 通过结构化因素保存总市值、触发日期、倍量倍数、30 日区间和最大回撤。

候选刷新服务增加该来源。候选合并仍按股票代码合并，但不同来源的证据保持独立，因此同一只股票同时命中九研、原有策略和新策略时不会覆盖或相加分数。

### API 契约

保持 `/api/v1/candidates` 的顶层结构和原有字段兼容，在 `CandidateSource` 中增加可选的结构化 `factors` 字段，并增加新的来源状态。现有客户端忽略新字段时仍能读取原有候选。

研究详情接口允许返回 `small_cap_absorption` 来源证据；`cross_hit` 继续只表示九点猫研与原有用户策略的双重命中，避免改变已有语义。详情页额外渲染新策略的结构化指标。

不新增刷新接口：新策略随现有候选刷新任务一起运行，共享任务状态和管理员权限边界。

### 前端布局

保留现有“我的选股策略”列，新增独立的“ 小市值倍量吸筹 ”列：

- 现有列只展示 `user_strategy` 来源，不把新策略混入原有列表或分数。
- 新列只展示 `small_cap_absorption` 来源。
- 卡片突出“首日倍量”，并显示股票名称、代码、总市值、触发日期、倍量倍数、30 日价格区间和最大回撤。
- 点击卡片继续打开同一个股票研究详情抽屉。
- 桌面端主研究区域从三列扩展为四列；窄屏按现有响应式规则堆叠，不隐藏新策略。
- 没有命中时显示明确的空状态；来源失败或使用旧快照时显示独立状态提示。

## 失败与降级

- 总市值行情接口失败：新来源标记 `error`，已有其他来源仍可展示；如果存在上一份小市值快照，则标记为 `stale` 并继续展示。
- 单只股票历史行情失败：跳过该股票，不影响其他股票。
- 快照为空或结构不完整：拒绝覆盖上一份有效快照。
- 既有用户策略仍只读取 `stocks`，新来源只读取 `small_cap_stocks`，相互失败隔离。
- 不生成模拟总市值、模拟 K 线或模拟候选。

## 测试范围

### 后端领域测试

覆盖：

- 总市值低于 100 亿元命中，等于或高于 100 亿元拒绝。
- 非主板、ST、退市股票拒绝。
- 2 倍阈值的边界值、前 5 日均量为零、成交量不足。
- 前 30 日存在倍量时拒绝。
- 最近三交易日信号识别，以及多个信号取最早日期并标记首日倍量。
- 价格区间 25% 和最大回撤 15% 的边界。
- 历史数据不足、缺失日期和无效市值的处理。

### Worker、来源与 API 测试

- 全市场行情只采集一次并过滤为主板小市值股票。
- `stocks` 与 `small_cap_stocks` 分离写入，现有策略不会读取新字段。
- 新来源能够从快照生成独立候选和结构化因素。
- 新来源与原有用户策略命中同一股票时保留两套来源证据。
- 新来源失败时保留旧快照并返回独立的 stale/error 状态。
- 候选 API 返回新来源，同时保留既有响应结构和双重命中语义。

### 前端测试

- “我的选股策略”不显示新来源。
- 新增“小市值倍量吸筹”列并展示“首日倍量”及结构化指标。
- 新策略候选能打开详情抽屉。
- 空状态、失败状态和窄屏布局不破坏现有工作台。

## 验收标准

1. 运行一次候选刷新后，原有策略列和新策略列均能独立显示或独立报告不可用原因。
2. 新策略候选严格满足上述 9 条规则，且能在详情中核对触发日期和计算指标。
3. 新策略不会改变九点猫研评分、原有用户策略评分或 `cross_hit` 的已有含义。
4. 旧快照和没有新策略数据时，现有股票研究功能仍可用。
5. 后端与前端新增测试通过，既有测试全部保持通过。
