# 全站统一认证、端口整理与模块联调设计

日期：2026-07-22

## 1. 目标

在不改变现有主站公开浏览体验的前提下，将守岸人原有账号体系抽离为全站统一认证服务，并让守岸人、股票研究模块和管理功能使用同一身份。同步解决论文查重端口与接口不一致、守岸人默认凭据和密码哈希缺陷、股票模块固定 `owner_id="local"`、股票上游嵌套 Git 仓库，以及本地服务端口混乱问题。

本阶段先完成本地开发、自动化测试和跨模块联调。正式上线时必须以宝塔服务器当前实际配置为准，合并现有股票路由，不使用本地旧 Nginx 文件覆盖线上配置。全部线上验证通过后才重写根目录 README。

### 2.1 本次包含

- 新建独立 `site-auth` 服务，提供全站用户、角色、会话和管理员认证能力。

## 4. 认证架构

### 4.1 服务边界

`site-auth` 独立维护 `auth.db`，只存储用户、角色和会话，不存储守岸人聊天数据或股票业务数据。守岸人和股票服务不直接读取认证数据库，而是通过仅绑定本机的内部会话验证接口取得可信用户身份。

认证服务至少提供以下接口：

- `POST /api/v1/session/login`：用户名或邮箱登录。
- `POST /api/v1/session/logout`：撤销当前会话。
- `GET /api/v1/session/me`：返回当前用户公开信息。
- `GET /api/v1/session/csrf`：提供修改类请求所需的 CSRF 值。
- `POST /internal/v1/session/verify`：供本机业务服务验证会话；必须携带内部服务凭据。
- 管理员用户接口：创建、禁用、启用、修改角色和重置密码；全部要求管理员身份。

不注册公开 `register` 接口。旧 `/api/auth/register` 停用，守岸人的 `/login.html` 和 `/register.html` 跳转到 SD 统一登录页。

### 4.2 会话安全

- 密码使用 Argon2id，并采用库提供的随机盐和参数升级机制。
- 不提供源码默认密码、默认 JWT 密钥或固定盐。
- 使用高熵不透明会话 ID；服务端只保存会话摘要，不保存明文会话值。
- 浏览器会话写入全域 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie，不写入 `localStorage`。
- 修改类请求使用双提交 Cookie 或等价 CSRF 校验，并校验 `Origin`。
- 登录成功支持受约束的同源 `next` 返回地址，拒绝外部 URL，防止开放重定向。
- 登录失败使用统一错误信息并进行基本速率限制；管理员可撤销用户全部会话。
- 内部验证接口只监听本机，并要求独立内部服务密钥。

### 4.3 初始管理员和旧账号处理

不迁移现有守岸人用户账号和旧密码哈希。上线切换时清理旧 `users`、`refresh_tokens` 等认证数据，但保留角色卡、聊天、语音、小说和股票数据。

管理员通过交互式 CLI 创建：密码由终端安全输入，不提供默认值、不在命令行参数和日志中回显。脚本支持显式重置管理员密码，但不会因重复执行而静默保留旧错误哈希。

任何清理生产认证数据的命令都必须先备份数据库，并要求显式确认目标数据库路径。

## 5. 页面与权限

### 5.1 公开内容

- SD 首页和工具箱。
- 股票首页、九点猫研候选摘要、公开晨报、公开历史晨报。
- 不涉及私人数据和付费资源的普通工具。

### 5.2 登录用户

- 股票个股详细分析、分析任务和个人模型 API 配置。
- 守岸人聊天、记忆、故事进度、语音和其他用户数据。
- 用户自己的模型配置、任务和报告。

### 5.3 管理员

- 用户创建、禁用、角色管理和密码重置。
- 守岸人原管理后台。
- 平台级模型配置和需要人工触发的系统任务。

所有权限必须由后端执行，前端隐藏按钮只用于改善体验，不能作为安全边界。

## 6. 模块改造

### 6.1 SD 主站

- 增加 `/auth/login` 统一登录页面。
- 增加全站会话状态组件，展示登录、退出和管理员入口。
- 提供统一的 `credentials: include` 请求封装和 401 跳转处理。
- 保持主页、工具箱和公开股票入口匿名可用。

### 6.2 守岸人

- 运行端口从 `8000` 改为 `8006`。
- 删除启动时自动创建默认管理员的行为。
- 停用固定 JWT 回退值、固定盐 SHA-256 和浏览器 `localStorage` Token。
- 旧登录和注册页面跳转至 SD 统一登录页。
- 聊天及用户数据路由接入统一会话依赖；健康检查和必要静态资源保持公开。
- 管理路由额外校验统一用户角色为 `admin`。

### 6.3 股票研究模块

- 公开候选、晨报和股票基础查询不要求登录。
- 分析任务、分析报告和模型配置路由要求登录。
- 用统一用户 ID 替换 `owner_id="local"`，确保模型密钥、分析任务和报告按用户隔离。
- 内部 `8003`、`8004` 继续使用现有服务令牌和路由签名，不向浏览器公开。
- 用户每次分析仍主动选择“自己的配置”或“平台配置”，不自动设置默认来源。

### 6.4 论文查重

- 服务端口改为 `8005`。
- 浏览器统一请求 `/plagiarism-api/api/v1/compare` 和健康检查接口。
- 统一上传字段和返回字段，由前后端共享类型或契约测试约束。
- 限制允许的 TXT、DOCX、PDF 类型、单文件大小和请求总大小。
- 错误响应不回显内部异常或服务器路径。

### 6.5 STM32

- HTTP/WebSocket 服务改为 `8007`，设备 TCP 改为 `8008`。
- 同步本地配置、SD 请求地址和 Nginx WebSocket 代理。
- 设备 TCP 端口变化必须在真实设备上线前单独验证，不在本地成功后直接假定设备已经切换。

## 8. 测试策略

所有行为修改遵循测试先行：先建立能稳定复现当前缺陷或缺失行为的失败测试，再写最小实现使其通过。

### 8.1 认证测试

- 正确密码登录、错误密码拒绝、禁用用户拒绝。
- 无公开注册接口。
- Cookie 属性、会话撤销、过期和管理员全会话撤销。
- CSRF 和非法 `Origin` 拒绝。
- `next` 只允许同源路径。
- CLI 创建与重置管理员，不存在默认密码和密码回显。
- 内部验证接口拒绝缺失或错误的服务凭据。

### 8.2 权限矩阵测试

- 匿名用户能读取主页、工具箱、候选和晨报。
- 匿名用户不能创建股票分析、读取私人报告或修改模型配置。
- 用户只能访问自己的模型配置、分析任务和报告。
- 未登录用户不能调用守岸人聊天和用户数据 API。
- 普通用户不能调用管理员接口。

### 8.3 查重测试

- 两个合法文件能完成比较，前后端字段一致。
- 错误字段、非法扩展、空文件、过大文件返回明确的 4xx。
- 健康检查和 Nginx 路径一致。

### 8.4 工程验证

- Python 测试和语法检查。
- SD、Openwrite、股票前端的类型检查与生产构建。
- 端口占用和服务健康检查。
- 浏览器端跨模块登录、刷新、退出和权限跳转联调。

## 9. 本地联调与上线

### 9.1 本地阶段

提供统一启动和健康检查脚本，按端口表启动必要服务。先验证公共页面，再创建临时管理员，依次验证统一登录、守岸人、股票分析、模型配置和查重。测试产生的认证数据使用独立测试目录，不覆盖真实业务数据库。

### 9.2 宝塔上线阶段

1. 备份宝塔当前 Nginx 站点配置、守岸人数据库和股票数据目录。
2. 读取服务器当前真实配置，确认已经存在的 `/stock/` 和 `/stock-api/` 规则。
3. 部署 `site-auth:8000`，再将守岸人迁移到 `8006`、查重迁移到 `8005`，按需迁移 STM32 端口。
4. 合并 Nginx 规则并先运行 `nginx -t`；失败时不重载。
5. 创建唯一管理员，确认统一登录后再停用旧守岸认证入口。
6. 验证公开页面、守岸人聊天、股票详细分析、用户 API 配置、管理员权限、查重和退出。
7. 检查日志中不存在密码、API Key、Cookie 或完整会话值。
8. 线上检查全部通过后重写根 README，使文档与真实部署一致。

没有服务器访问权限或宝塔当前配置时，只交付可部署产物、配置差异和验证脚本，不宣称完成线上发布。
