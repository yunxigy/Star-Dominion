# 完整股票目录与宝妈指数接入设计

## 1. 背景与目标

股票研究模块当前使用三只硬编码股票作为搜索目录，宝妈指数页面也只保留“等待接入”占位卡。本阶段完成两个相互独立、由股票主服务统一编排的数据能力：

1. 建立可搜索的沪深 A 股主板完整目录。
2. 将宝妈指数接入真实东方财富股吧和真实小红书数据。

宝妈指数仍是独立的反向情绪温度计，不读取、不修改九点猫研或个人策略的候选评分。任何生产接口和页面都不得使用模拟帖子或模拟历史数据。

## 2. 范围

### 2.1 包含

- 获取并持久化沪深 A 股主板代码和简称。
- 排除科创板、创业板、北京证券交易所、ST 和退市股票。
- 按代码、中文名称和拼音首字母搜索股票。
- 工作日自动刷新股票目录，并允许旧快照在外部数据源失败时继续服务。
- 每天北京时间 08:30 自动采集东方财富股吧和小红书。
- 管理员手动刷新宝妈指数。
- 管理员通过二维码建立、检查和更新小红书登录态。
- 展示四个板块的最新宝妈指数、来源状态、历史趋势和典型真实帖子。
- 清理或回收超时、遗留的运行中刷新任务。
- 更新测试、环境变量示例、启动脚本、健康检查和部署文档。

### 2.2 不包含

- 科创板、创业板、北交所、B 股、港股或美股目录。
- 小红书发布、评论、回复、点赞、收藏或关注操作。
- 小红书模拟数据回退。
- 宝妈指数参与候选池排序、评分或 AI 个股分析提示词。
- 增加新的公网服务端口。
- 使用历史行情回测宝妈指数的预测能力。

## 3. 方案选择

采用“股票主服务编排 + 独立一次性 Worker”方案。

- 股票目录 Worker 读取 AKShare，校验后写入目录快照。
- 宝妈指数 Worker 采集东方财富并通过本地 stdio 调用 Playwright 小红书采集器。
- `8002` 股票主服务负责公开读取 API、管理员控制 API、任务状态、调度和持久化。
- 网络采集和浏览器自动化不在 FastAPI 请求处理线程中直接执行。
- Worker 失败不会拖垮股票公开 API。

不采用以下方案：

- 将网络采集直接嵌入 `8002` 请求处理流程：Playwright、验证码和网络超时会阻塞主服务。
- 新建独立宝妈指数 HTTP 服务：当前规模不需要新增常驻进程和端口。

## 4. 开源小红书采集器

选择 `ShunL12324/xhs-mcp` 作为小红书只读采集能力：

- 上游地址：`https://github.com/ShunL12324/xhs-mcp`
- 许可证：MIT
- 技术栈：TypeScript、Playwright、SQLite
- 所需能力：二维码登录、持久登录态、登录检查、关键词搜索、时间筛选和笔记详情

集成要求：

- 固定经过验证的具体版本，不使用 `@latest`。
- 通过本地 stdio 启动，不开放 MCP 公网端口。
- 仅允许登录检查、二维码登录、搜索和读取笔记。
- 不注册或调用发布、评论、点赞、收藏等写工具。
- 登录数据库和浏览器状态保存在 `STOCK_XHS_DATA_DIR`，该目录必须被 Git 忽略。
- 上游地址、固定版本和 MIT 许可证记录在第三方来源文档中。

`jackwener/xiaohongshu-cli` 使用 Apache-2.0 许可证且支持结构化输出，可作为未来备用采集器，但本阶段不同时实现第二套小红书采集路径。

## 5. 完整股票目录

### 5.1 数据源

主数据源使用 AKShare `stock_info_a_code_name`。该接口返回 A 股股票代码和简称，不依赖股票当日是否有成交。

降级数据源依次为：

1. `stock_sh_a_spot_em`
2. `stock_sz_a_spot_em`

沪、深结果合并后进入同一套过滤和校验流程。目录数据不从新浪全市场实时行情获取，避免频繁调用导致临时封禁。

### 5.2 过滤与标准化

- 代码统一为六位数字。
- 上海主板仅接受 `600`、`601`、`603`、`605` 前缀。
- 深圳主板仅接受 `000`、`001`、`002` 前缀。
- 名称去除首尾空白。
- 名称包含 `ST`、`*ST` 或明确退市标记的记录不进入目录。
- 重复代码只保留一条；同一代码出现冲突名称时整次刷新失败。
- 每条记录计算交易所和名称拼音首字母搜索键。

### 5.3 持久化与替换

在 `hub.db` 新增股票目录记录和快照元数据。新目录先写入临时事务并完成以下校验：

- 有效记录不少于 1,000 条。
- 所有代码均符合主板规则。
- 代码唯一。
- 名称非空。

全部校验成功后原子替换当前目录。任何采集或校验失败都保留旧目录。

### 5.4 刷新策略

- 服务启动时目录缺失或过期则提交一次后台刷新。
- 每个工作日早晨刷新一次。
- 数据库租约保证多个 `8002` 进程中只有一个任务执行。
- 管理员可通过现有刷新编排显式刷新目录。
- 周末和法定节假日是否误触发不影响正确性；目录刷新是幂等操作。

### 5.5 搜索

`GET /api/v1/stocks/search` 保持现有参数，并支持：

- 完整或部分股票代码。
- 中文名称。
- 名称拼音首字母。

响应增加目录更新时间、来源和是否为历史快照。搜索结果仍只返回股票代码、名称和交易所。

## 6. 宝妈指数数据模型

### 6.1 板块

本阶段保留上游定义的四个板块：

- 纳斯达克
- 黄金
- CPO 通信
- 半导体

### 6.2 指标

每个板块保存：

- 综合宝妈指数，范围 `0–100`
- 宝妈买入指数，范围 `0–100`
- 宝妈卖出指数，范围 `0–100`
- 总帖子数、有效帖子数、小白帖子数和小白占比
- 买入、卖出帖子数量
- 风险区间与可读解释
- 最多三条典型真实帖子

风险区间固定为：

- `0–20`：极度冷清
- `20–40`：正常区间
- `40–60`：开始升温
- `60–75`：高度警惕
- `75–100`：极度狂热

### 6.3 来源状态

东方财富和小红书分别保存：

- `source_id`
- 状态：`ok`、`error`、`login_required`、`risk_controlled`
- 本次采集时间
- 成功采集的帖子数量
- 安全、可公开的错误摘要

Cookie、浏览器存储、手机号、二维码会话秘密和完整请求日志不得写入公开快照。

### 6.4 典型帖子

公开 API 中的典型帖子只包含：

- 平台
- 标题
- 原帖 URL
- 发布时间或采集时间
- 匹配理由
- 买入或卖出意图

不保存或公开手机号、Cookie、作者登录信息等私人数据。帖子去重优先使用平台 ID，没有稳定 ID 时使用规范化 URL 或内容哈希。

## 7. 采集与计算

### 7.1 东方财富

继续采集四个 ETF 股吧，但移除硬编码的 `127.0.0.1:7890` 代理。代理通过可选环境变量配置。每个板块独立记录成功或失败。

### 7.2 小红书

每个板块配置面向新手投资讨论的关键词。采集规则为：

- 优先筛选一天内发布的笔记。
- 每个关键词只读取有限数量结果。
- 搜索串行执行，并设置请求间隔。
- 同一笔记跨关键词命中时只保留一份。
- 登录失效返回 `login_required`。
- 验证码、访问限制或平台风控返回 `risk_controlled`。
- 不使用模拟帖子作为任何错误的回退。

### 7.3 部分成功

- 两个来源都成功：生成完整快照。
- 只有一个来源成功：使用本次成功来源生成“部分成功”快照，并明确标记缺失来源。
- 两个来源都失败：不生成新的指数快照，继续展示最近成功快照并标记陈旧。
- 不允许把旧来源数据与当天新来源数据合并后伪装成同一日完整快照。

## 8. API 设计

### 8.1 公开读取

- `GET /api/v1/mom-index/current`
  - 返回最新成功或部分成功快照、来源状态和陈旧状态。
- `GET /api/v1/mom-index/history`
  - 支持限制返回条数，默认返回最近 30 个真实快照。

### 8.2 管理员控制

- `POST /api/v1/mom-index/refresh`
  - 创建一次后台刷新任务。
- `GET /api/v1/mom-index/refresh/{task_id}`
  - 返回任务状态、来源结果和安全错误摘要。
- `POST /api/v1/mom-index/xhs/login`
  - 创建二维码登录会话并返回二维码图像或可安全展示的二维码数据。
- `GET /api/v1/mom-index/xhs/login/{session_id}`
  - 轮询登录进度。
- `GET /api/v1/mom-index/xhs/status`
  - 检查当前专用账号登录状态。

所有控制接口使用现有统一认证的管理员依赖。普通用户和匿名用户只能读取公开指数。

## 9. 调度与并发

- 时区固定为 `Asia/Shanghai`。
- 宝妈指数每天 08:30 自动刷新，包括周末。
- 股票目录在工作日早晨自动刷新。
- 时间以 UTC 持久化，API 明确返回带时区时间，前端按北京时间展示。
- 调度租约写入 `hub.db`，包括任务名、租约持有者和到期时间。
- 同一任务在租约有效期内不得重复启动。
- 超过最大运行时间的 `queued` 或 `running` 任务在启动和调度检查时回收为失败状态。
- 手动刷新与自动刷新共享同一租约和任务状态模型。

## 10. 前端设计

现有 `MomIndexPanel` 从占位卡升级为完整区域，同时保持当前浅色晨报工作台风格。

### 10.1 普通用户

- 四个板块指数卡。
- 综合、买入、卖出三个数值。
- 风险区间和解释。
- 东方财富、小红书来源徽标、帖子数和更新时间。
- 最近 30 个真实数据点的轻量趋势图。
- 典型帖子列表，可跳转原帖。
- 陈旧、部分成功、登录失效和风控状态的清晰提示。

### 10.2 管理员

- “立即刷新”按钮。
- 当前刷新任务进度。
- 小红书登录状态。
- “扫码登录／重新登录”入口。
- 二维码显示和登录轮询。

页面不得显示 Cookie、会话数据库路径、内部错误堆栈或敏感日志。

## 11. 错误处理

- 目录刷新使用原子替换，异常数据不覆盖旧快照。
- 外部来源设置连接和总任务超时。
- 每个来源独立捕获错误，避免一个来源中断全部采集。
- 对登录过期、验证码、风控、页面结构变化和网络失败使用不同错误代码。
- 自动刷新失败不影响晨报、候选、股票详情或 AI 分析 API。
- 公开错误只包含用户可采取行动的信息；详细诊断写入服务端日志并清除敏感字段。

## 13. 配置与部署

新增或调整环境变量：

- `STOCK_XHS_DATA_DIR`：小红书登录态和本地数据库目录。
- `STOCK_XHS_MCP_COMMAND`：固定版本的小红书 MCP 启动命令。
- `STOCK_MARKET_PROXY`：可选外部数据代理。
- `STOCK_MOM_REFRESH_TIME`：默认 `08:30`。
- `STOCK_TIMEZONE`：默认 `Asia/Shanghai`。

部署步骤包括：

1. 安装固定版本的小红书采集器及 Playwright Chromium。
2. 确认登录态目录不在静态目录、备份公开目录或 Git 跟踪范围内。
3. 启动股票主服务。
4. 管理员使用专用小红书账号扫码登录。
5. 运行只读搜索冒烟测试。
6. 验证 08:30 调度、手动刷新、部分失败和旧快照展示。

建议使用专用只读账号，限制每天搜索量。平台页面或风控策略变化可能导致采集失效，因此登录状态和来源健康必须可观测。

## 14. 验收标准

- 股票搜索不再依赖三只硬编码股票，能查询完整沪深主板目录。
- 非主板、ST 和退市股票不会出现在目录中。
- 目录更新失败时旧目录继续可用。
- 宝妈指数页面展示东方财富和小红书真实数据，并明确各自状态。
- 生产数据中不存在模拟帖子或模拟历史。
- 每天北京时间 08:30 自动刷新宝妈指数。
- 管理员可手动刷新并完成小红书扫码登录。
- 登录失效、风控和单来源失败都有明确状态，且不影响股票模块其他功能。
- 所有新增自动化测试通过，股票后端、分析服务和前端原有测试及生产构建继续通过。
