# 逐梦工具箱搜索流量、工具覆盖与使用效率升级设计

日期：2026-08-28
状态：待用户书面确认后进入实施计划

## 1. 背景与目标

逐梦工具箱当前由 React、TypeScript、Vite 和 React Router 构建，工具注册表包含 186 个工具和 17 个分类。最近两天已完成图片工作台与视频解析下载器的集中迭代，本轮不继续扩展音视频轻编辑能力，而是把投入集中到三个目标：

1. 让现有工具页和分类页更容易被搜索引擎发现、抓取和理解。
2. 上线搜索意图明确、开发风险可控的文本、站长 SEO 和 PDF 工具簇。
3. 缩短首页、工具目录和工具页的操作路径，提高桌面端与移动端使用效率。

## 2. 已确认范围

### 2.1 包含

- 修复线上 TLS 证书与协议配置问题；证书续签属于部署操作，仓库内只修改可确认的 Nginx 配置，不猜测线上证书路径。
- 为首页、工具目录、全部分类页和全部工具页生成独立、可抓取的静态 HTML 与 SEO 元数据。
- sitemap 从注册表自动生成，并覆盖首页、目录、分类和工具路由。
- 工具入口改为真实链接，默认同页打开，保留浏览器原生的新标签页行为。
- 首页 Hero、侧栏、工具目录、分类页和工具窗口的布局与可访问性升级。
- 增加文本效率、站长 SEO、PDF 深加工三个工具簇。
- 清理重复工具名称与重复搜索入口，旧地址通过显式映射兼容。
- 路由级懒加载、字体与动画优化，降低首页首次加载成本。

### 2.2 不包含

- 不新增音频裁剪、音频合并、视频截图、视频转 GIF 等“第四批：音视频轻编辑”功能。
- 不移除已经上线的视频解析下载器和现有音频工具。
- 不开发付费内容绕过、私有资源下载、去水印承诺、MD5 去重等高风险能力。
- 不在本轮重做品牌色、字体风格、图标体系或整体视觉语言。
- 不部署到生产环境；线上证书续签需要现有服务器或面板权限。

## 3. 首页与侧栏设计

### 3.1 首页 Hero

保持截图中现有暖色玻璃卡片、标题、渐变、搜索框和统计标签。把当前 Hero 下半部的空白改为“项目作品”紧凑入口区：

- 位置在搜索与统计信息之后，仍位于同一张 Hero 卡片内。
- 使用现有 `PROJECT_LINKS` 作为唯一数据源，不复制项目数据。
- 桌面端根据可用宽度显示 3–5 列；窄桌面不强制五列。
- 移动端采用横向可滚动卡片，首屏露出下一张卡片，提示用户可继续浏览。
- 每张卡片保留项目名称、短描述和方向图标；需要登录的项目继续执行现有登录跳转。
- 删除首页后半部分重复的“项目作品”大区块，避免同一入口出现两次。

右侧时钟与快捷分类卡片保持现有逻辑；当内容宽度不足以形成双栏时按当前响应式规则下移，不把非全屏截图造成的裁切误判为功能故障。

### 3.2 侧栏

侧栏的主要滚动区域全部用于工具目录：

- 保留品牌区、首页入口、全局工具搜索、工具分类目录、账号入口和最小版权/隐私信息。
- 从侧栏移除“项目作品”标题和五个项目链接。
- 分类目录占用移除项目区后的全部弹性空间，并保持独立滚动。
- 分类条目改为真实链接，目标为 `/category/:categoryId`，显示图标、名称和工具数。
- 当前分类具有明确的选中状态；工具详情页根据工具所属分类同步选中。
- 侧栏搜索从“搜索分类”升级为“搜索工具”：输入时显示匹配工具，结果为可抓取/可访问的真实链接；空查询时显示完整分类目录。
- 移动端继续使用抽屉式侧栏，点击入口后自动收起；菜单按钮补齐 `aria-label` 和 `aria-expanded`。

账号与版权属于侧栏外壳而非目录内容，继续保留但压缩高度，避免破坏现有登录和备案入口。

## 4. 导航与目录效率

### 4.1 真实链接

新增统一的 `ToolLink` 组件：

- 目标地址固定为 `/tool/:toolId`。
- 点击时记录最近使用，但不调用 `window.open()`。
- 支持 Ctrl/Cmd 点击、中键和浏览器上下文菜单。
- 首页热门工具、最近使用、收藏、目录卡片、分类页卡片和相关推荐全部复用。

工具窗口不再假设页面由脚本打开。关闭按钮改为面包屑和“返回分类/工具目录”入口，浏览器返回键保持原生行为。

### 4.2 工具目录

- 主卡片网格调整为 1/2/3 列，不再依据整个浏览器的 `xl` 断点强制四列。
- 工具标题允许正常换行，不再只显示开头字符；描述最多两行。
- 移动端分类筛选默认折叠为单个“筛选”按钮，已选分类显示为紧凑标签，确保首屏能看到工具结果。
- 搜索无结果时展示拼音/别名建议和可清除条件，不显示大面积空白。
- 收藏与最近使用继续保留，改为真实链接，并对收藏按钮保持独立点击区域。
- 超长列表使用 `content-visibility: auto`，只给首屏卡片播放进入动画，同时保持完整 DOM 链接供搜索引擎抓取。

### 4.3 工具页

- 图片工作台空预览高度缩至桌面 280–360px、移动端 200–240px；有内容时再扩展。
- 移动端主要操作按钮保持在参数区附近，不由站点固定页脚遮挡。
- 站点固定页脚在小屏变为普通文档流内容。
- 视频解析页只做导航、SEO 和布局一致性调整，不新增编辑功能。

## 5. SEO 架构

### 5.1 静态页面生成

采用仓库内可控的构建后静态页面生成器，不引入运行时 SSR 服务：

- 由注册表生成路由清单。
- Vite 正常构建后，为 `/`、`/gj`、每个 `/category/:id` 和 `/tool/:id` 输出对应目录的 `index.html`。
- 每份 HTML 写入独立 title、description、canonical、Open Graph、Twitter Card 和 JSON-LD。
- 静态正文包含页面标题、介绍、工具/分类真实链接、步骤与 FAQ；React 启动后接管交互界面。
- Nginx 优先提供已生成的目录页面，未知路由才回退到根 `index.html`。

该方案保持现有 Vite SPA 运行方式，不增加常驻 Node SSR 服务，同时让首个 HTML 响应包含可索引内容。

### 5.2 元数据模型

为工具与分类建立独立的 SEO 内容层：

- 工具：SEO 标题、摘要、搜索别名、适用场景、三步用法、隐私说明、FAQ。
- 分类：唯一介绍、能力列表、推荐工具、FAQ。
- 所有工具必须具备非空元数据；测试阻止新增工具遗漏 SEO 内容。
- URL、标题和 canonical 全部由统一站点配置生成，不在组件内硬编码域名。

### 5.3 sitemap 与结构化数据

- 构建时自动生成 `sitemap.xml`，禁止手工维护工具清单。
- 首页使用 `WebSite` 与 `SearchAction`。
- 分类页使用 `CollectionPage` 和 `ItemList`。
- 工具页使用 `WebApplication`；存在真实 FAQ 时再输出 `FAQPage`。
- 面包屑统一输出 `BreadcrumbList`。

## 6. 工具覆盖

### 6.1 文本效率工具簇

新增“文本工具”分类，首批包含：

1. 文本去空行
2. 文本行去重
3. 文本行排序
4. 批量查找替换
5. 文本增加/移除行号
6. 字符与词频统计
7. 邮箱、URL、IP 提取
8. 文本文件合并与拆分
9. Markdown、HTML、纯文本转换

这些工具复用无副作用的文本处理函数和统一双栏工作台。已有字数统计、大小写转换、文本对比和编码修复保留，但通过相关工具入口与新分类互链，不重复注册同名工具。

### 6.2 站长 SEO 工具簇

新增“站长工具”分类，分两层交付：

纯前端首批：

1. Meta 标签生成与检查
2. Open Graph 分享预览
3. robots.txt 生成器
4. sitemap.xml 生成器
5. URL 解析器
6. UTM 参数生成器
7. Slug 生成器
8. User-Agent 解析器

需要后端的检查工具：

9. SSL 证书检查
10. DNS 查询
11. HTTP 状态检查
12. WebSocket 连通性测试

后端网络请求统一使用显式协议白名单、DNS 解析后私网/环回地址拦截、重定向逐跳复检、响应大小限制和超时，复用视频解析服务已经形成的 SSRF 防护思路。

### 6.3 PDF 深加工工具簇

新增或从现有能力拆出明确入口：

1. PDF 添加页码
2. PDF 页面裁剪
3. PDF 页面尺寸调整
4. PDF 页面排序
5. PDF 转长图
6. PDF 元数据查看与清除
7. PDF 超链接提取
8. PDF 转 Word

已有页面编辑器或文档转换中心能够覆盖的能力使用共享处理核心和路由预设，不复制底层 PDF 逻辑。不会提供未知密码破解或绕过权限保护。

### 6.4 重复入口治理

- 合并或重命名重复的“图片加水印”、密码生成、文本对比和单位转换入口。
- 选择功能更完整的实现作为 canonical 工具。
- 旧工具 ID 保留显式重定向映射，避免外链和收藏失效。
- 注册表测试禁止重复名称、重复 canonical 和失效重定向。

## 7. 性能与可访问性

- `App.tsx` 中非首页路由改为 `React.lazy`，仅加载当前页面代码。
- 保持工具组件按 ID 懒加载，检查并避免首页预加载 PDF、报表和 AI 大模块。
- 自托管实际使用的字体，或回退到系统字体，减少中国大陆访问外部字体域名的等待。
- 动画尊重 `prefers-reduced-motion`；长列表仅首屏使用进入动画。
- 增加跳过导航链接、可见焦点、输入框标签、图标按钮无障碍名称和正确标题层级。
- 移除无替代焦点样式的 `outline-none`，避免泛用 `transition-all`。

## 8. 错误处理与数据边界

- 本地文本与 PDF 工具在文件过大、格式不支持和内存不足时显示可操作的错误信息，不上传文件。
- 后端站长检查返回统一状态：校验失败、连接超时、目标拒绝、被安全策略拦截、服务不可用。
- 搜索、收藏、最近使用的 localStorage 数据损坏时回退为空集合，不阻断页面渲染。
- 静态生成遇到缺失 SEO 内容、重复路由或无效 canonical 时直接令构建失败。

## 9. 测试与验收

### 9.1 自动化

- 为导航链接、最近使用记录、侧栏搜索、筛选折叠和项目入口编写 Vitest/Testing Library 测试。
- 为每个文本处理函数先写失败测试，再实现边界行为。
- 为站长工具的生成/解析核心与 SSRF 规则写单元测试。
- 为 PDF 处理核心覆盖页码、裁剪、排序、元数据和链接提取的最小样例。
- 为静态生成器验证全部工具/分类页面、canonical、结构化数据和 sitemap 一致性。
- 全量执行 `npm test`、`npm run lint`、`npm run validate` 和 `npm run build`。

### 9.2 视觉与交互

- 桌面端使用 1920×1080 全屏视口验证首页与侧栏，避免再次把裁切当成布局缺陷。
- 同时验证约 1366×768 的常见笔记本视口，确保分类仍可滚动访问。
- 移动端使用 390×844 验证首页、目录抽屉、筛选、图片工具和工具返回路径。
- 检查标题截断、卡片换行、底部遮挡、键盘焦点、减少动画模式和横向溢出。

## 10. 分阶段实施顺序

1. **基础与导航**：TLS 配置、真实链接、首页项目区、纯目录侧栏、目录/移动端布局、工具页返回路径。
2. **SEO 与性能**：元数据模型、分类内容、静态生成、自动 sitemap、结构化数据、路由懒加载。
3. **文本工具簇**：共享文本核心和 9 个独立入口。
4. **站长工具簇**：先 8 个本地工具，再 4 个受控后端检查工具。
5. **PDF 深加工**：共享现有处理核心并增加 8 个明确入口。
6. **重复治理与全量验收**：重定向、去重、全量测试、全屏与移动端视觉验证。

每一阶段保持可独立测试和回退；不把音视频轻编辑加入任何阶段。
