# 同花顺热门题材排序设计

## 目标

“我的选股策略”中的题材优先使用同花顺概念数据。一只股票可以属于多个概念，但页面最多展示 3 个，并把当前市场最热门、与个股上涨最同步的概念排在第一位。

## 数据源与降级顺序

1. 同花顺概念题材：主数据源，提供概念列表、概念热度和成分股关系。
2. 东方财富概念：同花顺请求失败、无有效数据或股票未匹配时的第一备用源。
3. 新浪行业：两个概念源均不可用时的行业兜底。
4. 题材暂不可用：所有来源均未匹配时使用，禁止生成虚假的统一题材。

同花顺接口按公开网页数据采集。概念列表和成分关系按交易日缓存，刷新时只更新必要数据，避免对每个候选股、每个概念重复请求。

## 热门题材排序

先取得股票所属的全部概念，再为每个概念计算当日热度。热度由以下指标组成：

- 概念当日涨幅：判断当前强弱。
- 概念成交活跃度：避免低成交概念仅靠少量股票拉升。
- 上涨家数占比：判断题材是否形成板块效应。
- 个股跟涨同步度：个股涨幅方向和强度是否与概念一致。

各指标先归一化，再合成为可比较的热度分数。概念当日涨幅和上涨家数占比权重最高，成交活跃度和跟涨同步度用于区分热度接近的概念。

每只股票按热度分数降序保留最多 3 个概念：

- 第 1 个概念是当前主线题材。
- 第 2、3 个概念作为辅助题材。
- 分数相同按概念名称稳定排序，保证相同输入产生相同结果。

## 数据流

每日 08:30 自动任务或管理员手动刷新时：

1. 读取同花顺概念清单和当日板块指标。
2. 建立股票代码到概念集合的映射。
3. 对候选股票的概念计算热度并排序。
4. 同花顺缺失的股票再查询东方财富概念。
5. 仍未命中的股票使用新浪行业。
6. 将最多 3 个有序题材写入用户策略快照。
7. 候选股仓库从新快照重建，前端继续使用现有 `题材：` 展示结构。

## 缓存与故障处理

- 同一交易日的概念清单和成分关系落盘缓存。
- 手动刷新优先更新当日板块行情，但可复用当日成分缓存。
- 单个概念请求失败不终止整批任务，记录失败并继续处理其他概念。
- 同花顺整体失败时自动进入东方财富和新浪降级链。
- 新快照为空时拒绝覆盖最近一次成功快照。
- 日志记录数据源、命中股票数、概念数、降级数量和失败原因。

## 代码边界

- 同花顺采集和解析封装为独立适配器，不把网页字段解析散落在策略逻辑中。
- 热度计算是无网络依赖的纯函数，输入板块指标和个股涨幅，输出可解释的分数。
- 现有快照模型继续使用 `concepts: list[str]`，无需改动前端接口。
- 新浪行业只负责最后兜底，不参与热门概念排序。

## 测试与验收

自动测试覆盖：

- 一只股票属于多个概念时，热门且跟涨同步的概念排第一。
- 最多保留 3 个概念。
- 概念分数相同时排序稳定。
- 同花顺部分失败时仍能处理其他概念。
- 同花顺整体失败时使用东方财富；两个概念源均失败时使用新浪行业。
- 所有来源失败时显示“题材暂不可用”，不再出现“全市场强势”。

实际数据验收：

- 同花顺概念列表能获取数百个概念，不以少量行业板块代替。
- 页面中不同股票显示不同的热门题材。
- 至少抽查 5 只强势股，第一题材与当日强势概念和个股走势方向一致。
- 自动刷新和管理员手动刷新均能生成非空快照。
