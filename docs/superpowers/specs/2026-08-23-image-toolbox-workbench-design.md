# 图片工具箱统一工作台设计

日期：2026-08-23

## 1. 背景

主站目前包含 12 个基础图片工具和 10 个图片增强工具。各工具独立实现上传、参数输入、预览、处理和下载流程，页面普遍采用紧凑单列布局。现状带来以下问题：

- 上传、参数和预览混排，桌面端空间利用率低。
- 不同工具的按钮、错误提示、空状态和下载流程不一致。
- 多数工具只支持单张图片，重复处理多张图片时操作成本高。
- 参数修改后需要反复点击预览，反馈不够及时。
- 部分工具使用浏览器 `alert()` 展示错误，任务上下文容易丢失。
- 各工具分别维护对象 URL 和 Canvas 生命周期，资源释放方式不统一。

本次升级借鉴参考页面的工作台布局，但保留主站现有浅色暖调视觉体系。升级范围覆盖全部 22 个图片相关工具，并同步加入符合各工具处理模型的批量能力。

## 2. 目标

- 为全部图片工具提供一致的上传、参数、预览、处理和下载体验。
- 在桌面端采用左侧控制、右侧预览的专业工作台布局，在移动端自然堆叠。
- 支持批量文件队列、进度、单项失败、重试和批量下载。
- 对适合实时反馈的单图操作提供参数变化后的自动预览。
- 保持图片处理在浏览器本地完成，不引入新的图片上传后端。
- 复用现有 Canvas、证件照分割模型和工具算法，避免无关功能重写。
- 建立共享组件和处理适配器，使后续新增图片工具可以复用同一工作台。

## 3. 非目标

- 不修改股票、OpenWrite、STM32、报告等其他模块。
- 不引入云端图片存储、账号图库或跨设备同步。
- 不在本轮加入历史项目保存、在线协作或复杂图层编辑器。
- 不改变各工具原有核心算法的业务含义；算法优化只在修复明确问题或支持批量所必需时进行。

## 5. 页面结构

图片工具继续运行在现有 `ToolWindow` 页面内。工具标题、描述和关联工具仍由外层页面负责，工具组件内部使用统一的 `ImageWorkbench`。

桌面布局：

```text
功能说明 + 本地处理标识

┌─────────────────┬──────────────────────────────────┐
│ 上传与参数区     │ 预览区                           │
│                 │                                  │
│ 拖拽上传         │ ┌──────────┬──────────┐          │
│ 文件信息         │ │ 原图     │ 处理结果 │          │
│ 批量文件队列     │ └──────────┴──────────┘          │
│ 工具专属参数     │ 缩放、适应、实际尺寸、背景切换   │
│ 常用预设         │                                  │
├─────────────────┴──────────────────────────────────┤
│ 状态 / 文件数量       重置  开始处理  批量下载      │
└────────────────────────────────────────────────────┘
```

- 左侧控制栏目标宽度为 360px，允许在 336px 至 400px 之间响应式调整。
- 右侧预览区使用剩余空间，最小高度随视口变化，避免大图挤压控制区。
- 平板端缩小控制栏并降低预览区最小宽度。
- 手机端按上传、队列、参数、预览、操作栏的顺序纵向排列。
- 批量文件队列使用缩略图卡片，支持选择、删除、排序、状态查看和逐项切换。
- 页面底部操作栏在长参数页面中保持可见，但不得遮挡内容。

## 6. 共享组件

### 6.1 `ImageWorkbench`

负责工作台布局、响应式结构、处理状态汇总和底部操作栏。它不包含具体图像算法，通过属性和插槽接收工具配置、参数面板和处理适配器。

### 6.2 `ImageDropzone`

支持点击选择、拖拽和剪贴板粘贴。展示支持格式、单文件大小限制、是否支持多选，以及“图片仅在浏览器处理”的隐私提示。上传失败在区域内显示，不使用阻塞弹窗。

### 6.3 `ImageBatchQueue`

管理文件缩略图、名称、尺寸、格式、体积和处理状态。状态固定为：等待、处理中、完成、失败。支持删除、重新排序、选择当前项、失败重试和清空已完成项。

### 6.4 `ImagePreviewPane`

提供三种查看方式：并排、结果单独查看、滑动对比。支持适应窗口、100% 实际尺寸、放大缩小、平移和透明棋盘格背景。预览区同时展示当前文件的原始信息与输出信息。

### 6.5 `ImageParameterPanel`

承载工具专属参数。公共输入样式、预设按钮、滑块、开关、单位和帮助文本由共享组件提供。支持“应用到当前”和“应用到全部”两种参数作用域。

### 6.6 `ImageActionBar`

统一提供重置、处理当前、开始批量处理、下载当前和批量下载。按钮状态由队列与处理状态决定，处理中显示总体进度和当前文件名称。

### 6.7 `useImageBatch`

集中管理文件队列、对象 URL、结果 Blob、任务状态、取消标记和资源清理。组件卸载、文件移除和结果替换时必须释放对应对象 URL、ImageBitmap 和临时 Canvas 引用。

## 7. 处理适配器

每个工具通过稳定的适配器接口接入工作台。适配器至少包含：

- 接受的 MIME 类型与文件数量规则。
- 默认参数与参数校验。
- 单文件或文件组处理函数。
- 输出文件命名与 MIME 类型。
- 预览生成策略。
- 批量模式和输出模型。

批量输出模型分为四类：

### 7.1 一进一出

适用于压缩、改尺寸、亮度、锐化、EXIF 清理、水印和加文字。每个输入文件生成一个输出文件，支持同一参数应用到全部，也支持逐项覆盖参数。

### 7.2 一进多出

适用于九宫格和 Favicon。每个输入文件生成一个结果组；下载当前结果组时打包为 ZIP，批量下载时按原文件名建立子目录。

### 7.3 多进一出

适用于图片拼接。队列顺序即合成顺序，队列整体作为一个任务处理。删除、排序或新增文件都会使现有结果失效。

### 7.4 交互编辑

适用于裁剪、取色、马赛克、证件照、截图美化、表情包和社交媒体封面。默认逐张编辑；可以将兼容参数应用到全部文件。裁剪比例、输出尺寸、背景、文字样式等可批量复用，而依赖具体坐标的选区允许逐张调整。

Base64 工具使用文本结果模型：图片转 Base64 为每个文件生成独立文本，可复制单项或打包下载；Base64 转图片支持多段输入解析并生成文件队列。

## 8. 交互行为

- 上传完成后立即显示原图缩略图、尺寸、格式和文件大小。
- 单图参数变化后等待约 200ms 再更新预览，连续输入只执行最后一次更新。
- 批量队列默认不因每次参数变化自动重算全部文件，用户通过“开始批量处理”明确触发。
- 常用尺寸、裁剪比例、压缩质量、社交媒体比例等以预设按钮展示。
- 输出区域在下载前展示格式、尺寸、预计或实际体积和文件名。
- 参数变化导致结果过期时，结果卡片明确标记“参数已变化，需要重新处理”。
- 单项失败后队列继续处理，失败项保留错误摘要和重试按钮。
- 关闭工具页面时取消未开始任务，并释放浏览器资源。
- 现有 `onClose` 行为由外层工具窗口管理，图片工作台内部不再重复放置“关闭”按钮。

## 9. 视觉规范

- 页面背景继续使用主站淡米色渐变。
- 工作台主卡片使用近白色表面和低对比棕灰边框。
- 主操作按钮使用现有深棕色强调色。
- 完成、节省体积和安全提示使用柔和橄榄绿。
- 失败状态使用克制的红色边框与浅红背景，不使用大面积高饱和红色。
- 上传区和空预览区使用细虚线边框，图标和说明保持明确层级。
- 控件高度、圆角、标签间距和帮助文本统一，减少紧凑小字。
- 预览画布支持浅色、深色和透明棋盘格背景切换，默认使用透明棋盘格。
- 动画仅用于上传反馈、状态变化和面板切换，并遵守 `prefers-reduced-motion`。

## 10. 性能与资源管理

- 优先使用 `createImageBitmap` 解码图片；不支持时回退到现有 `HTMLImageElement` 流程。
- 批量处理使用限量并发，默认并发数为 2；高内存任务可由适配器降为 1。
- 实时预览使用受限分辨率，下载时再按原始或目标完整分辨率输出。
- 对超大图片保留现有 50MB 单文件上限，并在解码前展示明确提示。
- 每个任务结束后释放临时 Canvas、对象 URL 和 ImageBitmap。
- ZIP 只在用户请求批量下载时生成，避免长期保留重复二进制数据。
- 不引入新的大型 UI 或图像处理依赖；优先复用浏览器 API 和现有依赖。

## 11. 错误处理

- 文件格式、大小、解码、参数、处理和下载错误使用结构化错误类型。
- 上传级错误显示在上传区，文件级错误显示在队列项，批量汇总错误显示在操作栏。
- 不再使用浏览器 `alert()` 处理正常业务错误。
- 单项失败不终止其他任务。
- 失败重试复用原文件与当前参数，不重复添加队列项。
- 结果失效、内存不足和浏览器能力缺失需要给出用户可执行的说明。

## 12. 可访问性

- 上传区支持键盘激活并提供明确的文件类型说明。
- 队列、参数和预览使用语义化区域标题。
- 所有图标按钮具有可读名称和可见焦点样式。
- 滑块同时提供数值输入，避免只能通过拖动操作。
- 状态变化通过 `aria-live` 适度播报，避免连续预览更新造成重复朗读。
- 颜色不作为状态的唯一表达方式。
- 桌面、平板和手机布局均保持合理阅读顺序。

## 13. 测试策略

### 13.1 单元测试

- 队列增删、排序、状态转换和失败重试。
- 参数作用域、结果失效和默认参数。
- 输出命名、MIME 类型和批量目录结构。
- 对象 URL 与处理资源释放。
- 四类处理适配器的输入输出约束。

### 13.2 组件测试

- 点击、拖拽和粘贴上传。
- 单图自动预览的防抖行为。
- 批量处理、单项失败和继续执行。
- 应用到全部、逐项参数覆盖和结果失效提示。
- 下载当前和批量 ZIP 下载。
- 键盘操作和主要可访问名称。

### 13.3 页面与构建验证

- 在 1440px、1024px 和 390px 宽度检查页面布局。
- 运行 TypeScript 检查、Vitest、工具注册表校验和 Vite 生产构建。
- 对高频工具执行真实图片冒烟测试，确认预览和下载结果尺寸、格式正确。
- 对多张大图执行批量处理，检查队列继续执行、页面响应和内存回收。

## 14. 实施阶段

### 阶段一：工作台基础与高频工具

建立共享组件、处理适配器和批量队列，迁移图片压缩、改尺寸、裁剪和基础水印。

### 阶段二：基础图片工具

迁移 Base64 转换、取色、拼接、九宫格、Favicon、证件照裁剪和证件照换底色。

### 阶段三：图片增强工具

迁移清晰度、亮度对比度、锐化、EXIF 清理、高级水印、加文字、马赛克、截图美化、表情包和社交媒体封面。

### 阶段四：统一收尾

完成移动端、键盘操作、批量 ZIP、错误体验、性能检查、视觉一致性和全部回归验证。

## 15. 验收标准

- 22 个目标工具全部使用统一图片工作台或与其处理模型匹配的共享变体。
- 22 个工具的原有核心能力保持可用。
- 支持多文件的工具均可从统一队列完成批量处理；特殊工具遵循本设计定义的多进一出、一进多出或交互编辑模型。
- 单图参数调整具备及时预览，批量任务具备明确触发、进度和失败隔离。
- 桌面、平板和手机布局均可正常操作，无横向内容溢出。
- 正常业务错误不再依赖浏览器 `alert()`。
- 图片仍在浏览器本地处理，现有证件照本地模型资源保持不变。
- TypeScript 检查、测试、注册表校验和生产构建全部通过。
