# Architecture

The framework separates research structure, evidence assets, orchestration state, and published artifacts so each layer can be validated and recovered independently.

```text
TaskSubmission + RuntimeProfile
  -> planner phases -> ReportNode tree + ResearchRequirement mapping
  -> evidence dispatch -> KnowledgeNode assets + EvidenceLink bindings
  -> reflection / structure guard -> repaired tasks and safe tree patches
  -> completion gate -> evidence quality + requirement coverage
  -> leaf-first writer -> grounded report draft
  -> publish gate -> report + audit artifacts
  -> run store / HTTP / CLI -> replay, cancel, review, resume
```

Core invariants:

- `ReportNode` models report structure, not source content.
- `KnowledgeNode` models a source asset, not a report claim.
- `EvidenceLink` is the auditable binding between a report node and a source.
- Agents request scoped tool operations; deterministic guards own structural mutation, completion, and publication decisions.
- Checkpoints recover execution state, while traces explain execution history. Checkpoint v3 uses atomic JSON/pointer writes and immutable checksummed event snapshots, with fallback to the newest valid retained checkpoint.

Completion uses evidence policy rather than interaction mode. During ordinary passes, unresolved error-level gaps create bounded repair work. At final completion, balanced/advisory mode classifies leaves by actual evidence/reportlet state: evidence-backed leaves become qualified, empty leaves are downplayed, and degradable unmet requirements receive framework-owned waivers keyed by stable requirement IDs. Strict mode and `failurePolicy=block` still pause. The writer applies those dispositions without exposing internal records, and the publish gate emits `publication-warnings.json`; citation integrity, forbidden sources, fabricated evidence, remaining overclaims, and render corruption are never force-published.

The leaf-first writer normally emits an executive summary, aspect sections, and a root conclusion. Deterministic assembly changes that layout in two cases: the task declares a fixed top-level count and the plan contains the same number of aspects, or the last aspect explicitly contains `Conclusion`/`结论`. A fixed contract can be stated directly as N or indirectly by introducing “the following sections”/`以下部分` and supplying a consecutive top-level 1…N list. For the latter form, normalization also recovers explicit bold/colon-delimited section names and their order as a non-evidence rendered requirement. If every named section must use bullets, the contract records that separately and checks each heading body for a Markdown bullet marker; a list in a sibling section or a numbered list is insufficient. If a smaller abstract count contradicts a longer complete First/Second/Finally or 首先/其次/最后 sequence, the concrete sequence count replaces it. The root conclusion is appended inside the final user section under H3, the executive summary becomes front matter, and no trailing H2 conclusion is emitted. Organizer acceptance and publication independently verify non-reference H2 count, normalized names, and order while allowing numeric prefixes and descriptive suffixes. Missing ancillary outputs stay under H3. Number extraction supports 2–12 in English and Chinese, ignores nested indentation, and rejects minimum-only wording.
- Provider usage is charged through one episode ledger before calls cross a hard budget boundary.

Within one evidence leaf, large temporal work is also structured. Explicit annual series are divided into year-by-year windows; long policy/event/development chronologies are divided into milestone windows of roughly three to four years. If the request asks how the main period relates to earlier laws or commitments, a bounded pre-period foundation reportlet is placed first. Each part carries its own search and writing goal, exact citations, and checkpointed `plannedReportlet` identity, then the leaf draft concatenates completed parts in order for upper-level synthesis. Publication-date ranges for literature reviews are not event timelines and are not sharded this way.

Two-sided analytical obligations are structured without turning them into unrelated top-level sections. Normalization detects explicit `on the one hand ... on the other hand` / `一方面…另一方面` clauses, removes directive boilerplate, and maps the pair to one unambiguous evidence requirement using local lexical overlap. It records two machine-readable perspective criteria plus a synthesis criterion. If the architect assigned that requirement to one coarse leaf, deterministic shaping replaces it with two sibling leaves under the same aspect and requirement ID. Each leaf's brief, guidance, objective, and acceptance criteria mention only its owned perspective; the sibling is referenced generically to prevent query contamination. Leaf reportlets are then compared by the ordinary bottom-up section writer. Ambiguous mappings and pairs that already have multiple planned leaves are left unchanged.

Rubric extraction also has a bounded omission guard. When the original input explicitly introduces three to twelve consecutive top-level numbered research tasks, normalization compares those items one-to-one with the model's substantive requirements. It restores only the positive count deficit, assigns stable `RQ_ENUM_*` IDs to the unmatched items, and sends them through ordinary leaf assignment, completion, and writing. Numbered language, Markdown, citation, bibliography, and length instructions are treated as presentation constraints rather than search leaves. This guard does not infer a research list from arbitrary numbered prose.

Restarted nested outlines use a different bounded guard. If a prompt explicitly introduces several 1…N groups—such as workflow stages followed by a fresh clinical-task list—each group must contain three to twelve consecutive items with bold, colon-delimited headings and a nearby controlled outline lead-in. Local lexical ranking maps every group to a different compatible evidence requirement; the ordered headings become member `entityScope`, and one unambiguous bold “for each item” field sentence becomes shared `metricScope`. The requirement is promoted to a rendered deliverable because the user explicitly requested one subsection per item. Evidence dispatch produces one field-complete reportlet per heading with bounded search/fetch scaling, and final organization accepts H3 or deeper subsections but rejects any missing or empty item. Ordinary numbered prose, unheaded instructions, ambiguous mappings, and cross-group scope pollution are left untouched.

Indented child-topic lists preserve a parent/child relation rather than becoming another flat scope. A numbered bold parent must explicitly introduce two to twelve categories/subsections, every indented bullet must have a bold colon-delimited heading, and any declared child count must match. A child-specific rubric requirement is marked as its owner; a broad parent that names several siblings is deliberately not repurposed, so missing children receive focused evidence requirements and ordinary dense-leaf shaping can split their searches. A separate evidence-free contract records the owning H2 and ordered child names. Final organization searches only inside that parent's Markdown extent for non-empty H3-or-deeper headings; the same title under a sibling H2 cannot satisfy it. Chinese task lead-ins such as “整理出以下几块内容” also recover the enclosing ordered H2 sequence. Unsignaled bullets, plain-text labels, and count mismatches remain prose.

Qualified global cutoffs preserve boundary direction. Chinese `中期` joins `年中` and `上半年` as a June-qualified period: inclusive wording ends June 30, while `中期之前` ends May 31 because the June period itself is excluded. English negations such as `not before mid 2021` are recognized as lower-bound wording and never inverted into an `as_of` ceiling.

Temporal eligibility has two explicit bases. `source_publication` constrains when an eligible study, paper, or perspective was published; `covered_period` constrains the events, availability, or measurements described, preserving the valid case where a later report explicitly covers an earlier requested period. An explicit global report/research/availability cutoff of either basis propagates onto compatible evidence requirements and all scout query classes. If the rubric model omits that globally worded constraint, normalization recovers one from the original input before tree planning. It also scans only the task text before any blocked-source directive for positively required quoted report/study/survey titles containing a strictly later year. A candidate must occur in its own affirmative instruction segment and lexically match an evidence requirement; the resulting `exemptSources` entry is attached only there. Negated titles, blocked-source directives, unrelated later titles, and titles not newer than the cutoff are ignored. The named-source scout query omits the bound, while all ordinary queries retain it. Natural-language year, month, and day cutoffs and range endpoints preserve exclusivity and inclusivity: an exclusive month starts by subtracting one day from that month's first day, an inclusive month ends on its last day including leap years, and `January 2020 to August 2023` remains `2020-01-01` through `2023-08-31`. Qualified periods use quarter ends (`early`/Q1/`年初` = March 31, `mid`/Q2/first half/`上半年` = June 30, Q3 = September 30, late/Q4/second half = December 31). Search operators now follow the same basis distinction: a source-publication range adds `after:` for the calendar day before its inclusive start and `before:` for the day after its inclusive end; a covered-period range/as-of rule uses the same normalized endpoints only in explicit `covering period/evidence` terms and never filters document publication dates. This avoids fetching pre-window literature while preserving later sources that explicitly cover an older target period. Quality audit uses normalized publication or coverage metadata accordingly; only `current` mode retains clock-skew tolerance. `exemptSources` remains an exact named-source escape hatch, never a general date waiver.

Named multi-field comparisons follow the same row-first invariant. `entityScope` supplies exact row subjects and `metricScope` supplies exact requested fields, including categorical fields. Normalization recognizes prefix counted lists such as “the following 13 countries”, Chinese postpositive lists such as “A、B……这五个城市”, and count-before-parentheses lists such as “10种系统制式（A、B……）”. It accepts only 2–20 unique names whose parsed count exactly equals the declaration, preserves order and conjunctions, and maps each local list only when one evidence requirement is a clearly better row/profile target than aggregate siblings. When an identical list appears in two clauses, a requirement that already owns it is removed from the next ranking; reassignment occurs only when another requirement has both a type match and sufficient lexical overlap. This prevents recovery-generated criteria from monopolizing repeated scopes. The user-owned list replaces partial or polluted model scopes and is marked `members`. Scout treats an explicit structured member scope plus metrics as sufficient authority-query intent, expands every name under the existing cap, and round-robins across requirements. The architect then batches five or more subjects into bounded leaves of roughly three members under the hypothesis cap. Each leaf produces complete cited rows that merge bottom-up. Open category lists still use `groups`; exact table schemas and plural academic cues retain their existing recovery paths. Different entity sets remain isolated, and runtime budgets scale with bounded reportlet groups rather than cells.

Wide partitioned comparisons add two conservative contracts. First, a numbered 0…N or 1…N list introduced as comparison dimensions can restore a partial `metricScope`; a Security field expands only when its line explicitly names two or more attack/threat subdimensions. This recovery targets one unambiguous table or a bounded set of entity-scoped tables that are explicitly the named partitions, so unrelated tables do not inherit the fields. Prefix entity parsing treats ASCII dots inside product/framework names as data and still validates the declared count. Second, a sentence that explicitly requests two tables and names both partitions creates `RQ_TABLE_PARTITION_CONTRACT` only after a compatible complete member scope exists. Each entity reportlet classifies itself into exactly one label from direct evidence. Rendering then requires exactly the labeled table count, every entity in a first-column row, and zero cross-table duplicates. The guard verifies conservation and labeling rather than hard-coding semantic membership; the cited reportlets and semantic reviewer remain responsible for whether each classification is correct.

Mandatory named narrative cases have a separate invariant. Directive-local lists such as “illustrate with A, B, and C” or “focus on the stories of A, B, and C” are conservatively mapped to one unambiguous substantive requirement as `exampleScope`. They are not `entityScope` members: the tree keeps the broader analytical leaf, while evidence dispatch creates one internal cited reportlet check per example and scales a bounded search/fetch budget with the list. Quality audit requires substantive cited text for every name, emits `incomplete_example_coverage` with the exact omissions, and completion creates a focused repair that reuses cached evidence first. This preserves top-down analytical structure and bottom-up case synthesis without exploding narrative examples into fake comparison tables.

Derived inequality metrics stay inside that evidence boundary but do not depend on model arithmetic. The evidence registry exposes one deterministic `calculate_distribution_indices` operation for 2–64 matching weight/value entries. It validates finite positive weights, nonnegative values, optional matching labels, and the Atkinson epsilon; then returns normalized shares, relative concentrations, Atkinson, Hoover ratio/percent, and Theil. The reportlet cites the external sources that supplied the arrays and treats the result as a transparent derivation. Missing inputs stop the calculation and remain an open gap, preventing plausible-looking statistics from being synthesized from guesses.

Open taxonomies use `entityScopeRole=groups` to distinguish discovery categories from already-known final rows. The architect creates one bounded leaf per requested group. Each leaf searches authoritative inventories or primary literature, discovers multiple concrete members, verifies category membership, deduplicates aliases, and fills every requested field for each member without inventing a quota. Category reportlets merge bottom-up into grouped tables or sections; quality audit requires substantive cited coverage for every group but deliberately does not create false category-field cells. A category leaf targets one search and two full-source fetches while retaining the normal hard budget ceilings.

The initial scout allocates its fixed query budget across requirements rather than concatenating one requirement's expanded entities first. Authority query lists are interleaved round-robin; exact named-source exceptions stay ahead of that pool. When multiple requirements or LLM-planned searches compete, the allocator reserves at most two broad slots—one leading planned query and the fallback—while leaving at least one authority slot. Unused or duplicate reservations are backfilled without increasing the configured query cap. Search-result lists are independently interleaved by publisher/query downstream, so fairness applies both before and after provider calls.

Repeated case-study/profile/category deliverables reuse the entity-field contract without forcing table output. The architect normally assigns one named entity per leaf; if several share a leaf, evidence dispatch creates one complete reportlet per entity. When the user requests both detailed sections and a summary table, that reportlet explicitly supplies reusable narrative plus a concise row from the same cited facts. During final assembly, the rendered-deliverable guard resolves parenthetical aliases and common category shorthand, requires a non-empty Markdown section for every scoped entity, and requires one summary-table block whose first column covers every entity. It reports exact missing section names and table rows; organizer output is accepted only after both obligations are complete.

Multi-table presentation contracts remain separate from column contracts. A conservative shared parser recognizes explicit counts from 2–12 in English or Chinese, including a complete first/second/third or 第一/第二/第三 sequence, but ignores column counts and maximum-only wording. If the rubric model reduces an original request for N tables to one generic table deliverable, normalization adds the missing count criterion to that sole deliverable. Final organization and publication then require at least N distinct Markdown table blocks in its section. A failure is a report-rendering repair and does not spend another evidence-search call.

Counted empirical-study reviews have a shared 6–60-row contract parser used by tree planning and final rendering. Geographic or methodological leaves contribute complete cited study reportlets toward one collective minimum; gap consolidation counts distinct eligible primary sources. Final organization separately verifies that one table preserves the requested `metricScope` header order and contains enough complete, distinct, cited rows. Blank, explicitly unavailable, uncited, or duplicated rows are excluded. `publish-gate` repeats this check after organization and treats failures as report-rewrite defects, avoiding redundant search dispatch when the evidence gate itself has no deficit.

The completion and publish boundaries produce durable quality artifacts. `evidence-quality-audit.json` records source depth, independence, authority, fetched-content status, explicit numeric or categorical entity/field cells, requirement coverage, waivers, and citation grounding. Matrix creation is conservative: a study-publication window, chronological policy window, narrative region list, or categorical answer legend remains scope metadata rather than becoming a row entity. `budget-audit.json` records provider usage, estimated cost, breaches, cycle gains, and adaptive-stop state. The artifact-level regression gate evaluates those files without repeating external calls; see [`QUALITY_REGRESSION.md`](QUALITY_REGRESSION.md).

The HTTP abstraction accepts a `ResearchRunStore`. The library keeps an in-memory default for tests and stateless embedding, while the example server injects the SQLite WAL implementation for durable run IDs, replay, heartbeat, cancellation, and checkpoint discovery. See [`RUN_STORE.md`](RUN_STORE.md).

Detailed agent/runtime behavior remains specified in [`SPEC_V6.md`](SPEC_V6.md); v5 data boundaries are documented in [`SPEC_V5.md`](SPEC_V5.md).

Architecture is evaluated rather than followed mechanically. The preserved product model is top-down task/report-tree exploration followed by bottom-up leaf/section/synthesis writing. DeepResearch Bench II rubric pass rate, together with duration, cost, recovery, and failure records, is the primary optimization loop; see [`DEEPRESEARCH_BENCH_II.md`](DEEPRESEARCH_BENCH_II.md).
