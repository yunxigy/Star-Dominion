# Research Requirement Traceability

The framework maintains a deterministic chain from the user's request to the published report:

```text
User request
  -> GlobalRubric.requirements[]
  -> ReportNode.requirementIds[]
  -> EvidenceLink / Reportlet
  -> leaf and aspect drafts
  -> requirementCoverage in evidence-quality-audit.json
```

## Requirement contract

Each `ResearchRequirement` has a stable ID, description, kind, priority, `evidenceRequired`, evidence needs, observable success criteria, optional geographic and temporal scopes, optional `entityScope` plus `entityScopeRole` for named rows/profiles or discovery groups, optional `exampleScope` for mandatory named narrative cases, and optional `metricScope` for exact requested fields/columns/dimensions. `metricScope` retains its compatibility name but supports categorical as well as quantitative fields. Entity and field scopes have a wider normalization limit than ordinary evidence/criterion lists, so wide matrices do not lose their final columns. `exampleScope` remains narrative and never activates matrix cells. Presentation constraints such as language, format, length, or organization use `evidenceRequired=false`; they are checked on the rendered report rather than by demanding an irrelevant external source.

- `must`: drives repair and must never be falsely reported as complete. With `failurePolicy=degrade`, balanced/advisory mode may publish the verified subset after bounded repair with an audited omit/downplay disposition; strict mode still blocks. `failurePolicy=block` is non-waivable in every mode.
- `should`: missing coverage is visible as a warning.
- `exploratory`: missing coverage is informational.

`visibility` is independent: `reader` requirements remain in writer context, including blocking substantive obligations, while `internal` policy constraints are enforced without being printed. This avoids using one flag for two unrelated decisions and leaves free-text recognition only as backward compatibility for older rubrics.

Temporal scopes support `current`, `historical`, `as_of`, `range`, and `timeless`, plus a semantic `basis`. `basis=source_publication` limits when eligible evidence was published; `basis=covered_period` limits the events, availability, conditions, or measurements described by evidence. English and Chinese year/month/day expressions are normalized deterministically. “Before/prior to March 2025” and “2025年3月前” become `2025-02-28`; “through/as of March 2025” becomes `2025-03-31`; explicit days and leap years are validated. Range endpoints use the same parser, so “from January 2020 to August 2023” becomes inclusive `start=2020-01-01` and `end=2023-08-31` for either basis rather than being rounded to whole years. Qualified year periods use calendar-quarter ceilings: `early`/Q1/`年初` → March 31, `mid`/Q2/first half/`上半年` → June 30, Q3 → September 30, and late/Q4/second half → December 31. A plain event narrative such as “how policy changed through 2018” remains historical unless it actually declares an availability/inclusion cutoff. `exemptSources` contains only exact user-required sources outside the boundary.

For explicit structured multi-entity deliverables, `entityScope`, relevant `geographicScope`, and conservatively inferred subjects are audited. `entityScopeRole=members` means each named subject is a final row/profile. If the original input declares “the following N countries/cities/companies/products/frameworks/materials/technologies/industries/organizations/species”, a Chinese postpositive enumeration ending in “这/上述 N 个对象”, or a count followed by a parenthetical system/type list, normalization validates N and recovers the ordered list onto the best-matching evidence requirement. Postpositive parsing takes the final N delimited names from the local sentence and removes only a bounded presentation verb from the first item; parenthetical parsing leaves names untouched. Both reject count mismatches, duplicates, oversized items, and ambiguous mappings. Lexical type, row/table intent, sentence-local overlap, and an aggregate-index penalty prevent the list from leaking into regional summaries. Repeated identical scopes may map to separate requirements only after excluding an existing exact owner and finding another strong type-and-context match. `entityScopeRole=groups` instead marks discovery categories whose concrete members are not known in advance. Member tables can expose exact entity-field or entity-year-field cells; group mode exposes category coverage and cited discovery reportlets. Narrative analysis does not acquire an artificial matrix.

Range semantics are separated from value completeness. “Every year” and explicit quantitative comparisons activate year cells, but “studies published from 2009-2024” and “policy events from 2005-2015” are corpus/timeline bounds rather than endpoint-value requests. Narrative geographic overviews likewise do not activate entity value cells. Parenthetical entity inference requires an entity-type cue such as cities, countries, companies, or products, so categorical table values are not treated as missing subjects.

New rubric output should populate `entityScope`, `entityScopeRole`, and `metricScope` directly. If it omits one unambiguous original table contract, normalization can recover an explicitly enumerated 2–12-column header sequence and one unambiguous required category list. It stores the header order in `metricScope`, marks the categories as discovery `groups`, and adds an observable exact-header criterion. Ambiguous prompts with multiple schemas or multiple candidate table requirements are left to the rubric rather than guessed. Older checkpoints remain usable: an omitted role retains member/row behavior, while the audit conservatively infers quantitative field names from repeated labels followed by recognizable units and uses existing geographic scope where appropriate. Markdown tables, row-oriented text, and grouped prose such as “ridership: Beijing…, Shanghai…; intensity: Beijing…, Shanghai…” are supported.

## Planning and repair

The rubric phase preserves every explicit question, comparison, output constraint, geography, and time boundary as a separately testable requirement. The architect copies exact requirement IDs to aspects and leaves.

An explicit two-sided clause is one substantive requirement with three observable criteria rather than two unrelated report sections: one `Research this explicit perspective separately:` criterion per side and one comparison/synthesis criterion. English `on the one hand ... on the other hand` and Chinese `一方面…另一方面` pairs may use a semicolon or sentence boundary. Directive prefixes such as “please explain how” are removed before storage. Contextual one-to-one ranking attaches the pair only when one evidence requirement is clearly better than its siblings; ambiguous pairs are not guessed.

For an explicitly introduced consecutive list of three to twelve numbered research tasks, normalization does not assume the rubric model preserved every item. It performs one-to-one lexical matching against substantive question/comparison/deliverable/risk requirements and restores only a positive count deficit. Each unmatched task receives a stable `RQ_ENUM_*` evidence-bearing `must` requirement, is assigned to the most relevant real leaf, and therefore participates in ordinary evidence completion and bottom-up writing. The detector requires a task/question/requirement lead-in and filters numbered language, Markdown, citation, bibliography, and length instructions, so an output checklist does not create redundant searches.

Several nested numbered lists may legitimately restart from 1 under different parent sections. Normalization treats each such 3–12-item group independently only when it has a controlled nearby outline lead-in and every line begins with a unique bold heading followed by a colon. Contextual ranking binds each group to a different compatible evidence requirement, stores its headings as ordered member `entityScope`, and copies a single unambiguous bold “for each item” dimension list into `metricScope`. It also records explicit all-item coverage, per-item dimension, and per-item subsection criteria and promotes the obligation to `deliverable`. Evidence planning therefore creates one complete reportlet per item instead of one oversized query, while ordinary lists without the lead-in or headings remain unchanged.

A nested bullet hierarchy has two linked traces. First, every bold child topic under an explicitly subdivided numbered parent is mapped one-to-one to a child-specific evidence requirement; if the model supplied only a broad parent requirement, that parent remains intact and focused `RQ_NESTED_*` requirements recover the children. Full and parenthetical-short heading aliases are considered, but one requirement that names multiple siblings cannot impersonate a focused child. Second, `RQ_NESTED_SECTION_CONTRACT_*` records the exact parent H2 and child headings with `evidenceRequired=false`. This keeps research completion and Markdown placement independently observable: cited child evidence can block completion, while a child heading rendered under the wrong parent can block publication.

Global report/research/public-availability time rules are propagated onto compatible evidence requirements instead of relying on the model to repeat the same boundary in every sub-question. If rubric output omits or coarsens a clearly global rule present in the original task, deterministic normalization restores/corrects a must constraint before propagation; local section-specific dates do not match this recovery pattern. When the original task positively requires an explicitly quoted report/study title bearing a year later than the global cutoff, normalization can also restore that one narrow exception and map it to the best-matching evidence requirement. Extraction stops before blocked-source directives, uses sentence-local affirmative/negative cues, and never turns a later year or publisher into a general waiver. Source-publication rules are additionally mapped to every evidence-bearing leaf. Their deterministic authority and planned/fallback queries carry a next-day-exclusive `before:` ceiling and, for a range, an `after:` floor set to the day before the inclusive start. Covered-period queries carry the normalized dates as semantic coverage terms but deliberately omit publication-date operators. Exact named-exception queries omit publication bounds. For `as_of`, audit converts the normalized date to that day's inclusive final millisecond and evaluates source coverage metadata before falling back to publication dates; it does not apply the one-day clock tolerance reserved for `current` questions.

Evidence dispatch preserves the difference between numeric series and event chronology. A long chronological policy/event/development leaf is divided into ordered milestone reportlets of roughly three to four years, with an optional pre-period foundation part only when the task asks about previous laws, definitions, or commitments. Each part searches and writes within its own window and explicitly does not require an event in every year. Broad repair tasks retain this decomposition, while atomic writer/publish repairs remain unsplit. Literature inclusion/publication windows are excluded from event sharding.

Explicitly required named examples are also preserved without changing the report hierarchy. A directive-local proper-name list introduced by wording such as “illustrate with”, “focus on”, “pay special attention to”, or “specifically analyze” is recovered only when one substantive requirement is the clear lexical owner. Its ordered names populate `exampleScope` and an observable cited-analysis criterion; `entityScope` remains empty unless the task independently asks for rows or profiles. Evidence dispatch creates bounded internal reportlets for the examples, and the quality audit counts an example only when a direct EvidenceLink claim/quote or cited reportlet both names it and contains substantive surrounding analysis. A missing name produces `incomplete_example_coverage`, blocks a `must` requirement, and creates a cache-first repair naming only the omissions. Once every example has cited analysis, the ordinary leaf/section/root writers synthesize them bottom-up.

When a requirement asks for Atkinson, Hoover, or Theil distribution indices, traceability extends through the derived result. The evidence agent passes exact, equally ordered labels, positive weights, and nonnegative values from saved sources to `calculate_distribution_indices`; it never substitutes guessed or zero-filled inputs. The tool normalizes `w_i = weight_i / sum(weights)` and `p_i = value_i / sum(values)`, reports each `p_i / w_i`, and calculates Hoover as `0.5 * sum(abs(p_i - w_i))`, Theil as `sum(p_i * ln(p_i / w_i))`, and Atkinson for the requested epsilon with explicit zero-share handling. Reportlet citations continue to point to the KnowledgeNode/EvidenceLink inputs because the deterministic result is a derivation, not independent evidence. A missing input therefore remains a cited coverage gap rather than a fabricated statistic.

Before dispatch, a requirement with exactly two recovered perspective criteria and exactly one mapped leaf is expanded into two sibling leaves when capacity permits. Both retain the parent requirement ID so completion remains traceable, but each task names only its own perspective and demands direct primary, official, or authoritative scholarly evidence plus mechanisms, context, consequences, and qualifications. The sibling text is deliberately omitted from its search-facing brief to avoid mixed queries. The section writer receives both cited reportlets and performs the higher-level comparison; if either leaf remains unresolved, normal task/gap completion prevents a one-sided draft from masquerading as full coverage.

For named comparison tables and repeated case profiles, planning is entity-first. The architect assigns every member exactly once. Five to twenty declared members are now authoritative expansion input even if the requirement description says only “every requested country”: subjects are balanced into as many roughly three-member leaves as the current hypothesis cap permits, and every task names only its owned subset. For open taxonomies, recovered category lists instead assign each parent group once and let that leaf discover concrete members. Scout derives concise authority or academic queries from the same scope; evidence dispatch fills every field in each row rather than splitting by columns. Compatible sets can merge, independent sets remain isolated, targeted repairs address known member cells, and open groups use category coverage. Exact recovered headers remain mandatory at organizer and publication boundaries.

An explicitly numbered comparison-dimension list is another trace source when the rubric returns a partial matrix. Its bold headings populate `metricScope`; a generic Security heading is replaced by its explicitly enumerated attacks only when at least two are named on that line. Recovery is skipped when several unrelated table requirements make ownership ambiguous. Counted prefix entity lists also preserve ASCII dots inside names before performing exact count and uniqueness validation.

Named two-table partitions carry a separate non-evidence `RQ_TABLE_PARTITION_CONTRACT`. The evidence-bearing table requirement records the allowed partition labels, so every entity reportlet researches one classification and its basis alongside its ordinary fields. The render contract retains the union member scope and checks exactly two labeled Markdown blocks, first-column coverage for every member, and an occurrence count of exactly one per member. Missing and duplicated names are returned separately to report organization and publication. This does not claim semantic correctness from string matching: the evidence and semantic publication review must still justify why an entity belongs to its chosen partition.

When several structured requirements each expand into many entity queries, scout interleaves one query per requirement per round before taking the next entity. An explicit `entityScopeRole=members` with 2–20 names and at least one metric is itself sufficient to trigger per-member authoritative search, even when the requirement text does not repeat generic authority keywords. Scout still preserves bounded planned/fallback coverage under the same hard limit. Thus requirement wording and order cannot silently remove an entire later matrix or narrative branch from the initial source map.

Rendered structure is checked separately from evidence coverage. When a must deliverable requests one independent section or subsection per named entity—including `subsection for each/every` wording recovered from a nested outline—`report.ts` resolves full names, parenthetical aliases, common category shorthand, and specific Chinese heading phrases of at least three Han characters inside longer requirement descriptions; it verifies a non-empty H2-or-deeper heading/body for each entity and sends the precise missing list to the final organizer. Parent-bound contracts further restrict child headings to the Markdown extent of their declared H2, so a correct H3 under the wrong sibling remains missing. A compound requirement may simultaneously demand those detailed sections and a summary table. In that case neither format short-circuits the other: one Markdown table block must contain every entity in its first column, and missing table rows are reported by exact entity name. A generic section or an unrelated experimental-data table cannot satisfy the compound deliverable.

Ordinary member comparison tables now receive the same final row-conservation check even when no independent entity sections were requested. Across all table blocks inside the deliverable section, every scoped member must occur in a first-column row. Partition contracts strengthen this to exactly one occurrence across exactly labeled tables; ordinary multi-table deliverables allow repetition because the same members may legitimately appear in separate metric tables.

An explicit request for 2–12 separate tables is also a rendered contract. English/Chinese cardinal wording and complete ordinal sequences are parsed from the original task and normalized requirement; if one generic table deliverable lost the original count, its success criteria recover it. The report guard counts distinct Markdown table blocks inside the deliverable section, reports expected versus observed counts, and repeats the check at publication. “Three columns” never means three tables, and “at most three tables” is not converted into a minimum. Missing blocks are repaired from existing cited reportlets rather than being misrouted into evidence search.

For a table that explicitly requires at least 6–60 empirical studies, the collective minimum is parsed once and reused by the architect, counted-row gap consolidation, report organizer, and publish gate. Rendering is complete only when the table header exactly follows the declared `metricScope` order and at least N unique full rows remain after excluding duplicates, missing-value cells, and rows without a citation marker. If bounded research establishes fewer than N rows under a downplay disposition, the same schema and at least one verified cited row remain required, and reader-facing prose reports the achieved N-of-M coverage. Without that audited disposition, the partial table remains a non-dispatchable render defect.

A fixed-count top-level layout is also testable structure. Direct phrases such as “divide the answer into three sections” or “包含四个主要部分” are parsed conservatively. So are indirect contracts that introduce “the following sections”/`以下部分`/“整理出以下几块内容” and then provide a consecutive, unindented 1…N list; nested numbered details do not enlarge the count. When those items expose explicit bold or colon-delimited titles, normalization adds a non-evidence `RQ_TOP_LEVEL_SECTION_CONTRACT` containing the ordered names. If the task also says each section must be bulleted, the same contract requires a real Markdown bullet list inside each named heading body. A contradictory smaller count is replaced only by a longer complete substantive First/Second/Finally or 首先/其次/最后 sequence; minimum-only enumerations remain open-ended. Root synthesis is placed as H3 inside the final user section and the executive summary becomes front matter. Organizer candidates and publish output are checked for H2 count, normalized names, and order, with numeric prefixes and descriptive suffixes allowed. A list in one section cannot satisfy siblings, numbered prose cannot satisfy an explicit bullet contract, ancillary outputs stay under H3, and reference headings are excluded. These render defects cannot be force-published or misrouted into evidence search. An explicit final `Conclusion`/`结论` aspect retains the same merge behavior.

Model output is not trusted blindly. Invalid IDs are discarded, numbered-task omissions are recovered conservatively from the original input, and every resulting requirement omitted from the proposed tree is deterministically assigned to the most lexically relevant leaf. Requirement IDs are rolled up to containing aspects for section synthesis.

Completion does not treat an evidence-bearing mapped requirement as covered merely because the node exists. At least one mapped active leaf must contain direct supporting, qualifying, or contradicting evidence. Background-only material is not coverage. An unmapped `must` requirement cannot be skipped by automatic mode.

Temporal, entity, and field coverage are part of the same completion loop. An `incomplete_temporal_coverage` or `incomplete_entity_coverage` issue blocks a `must` requirement, creates a repair task with the exact missing years/entities/fields/cells, and is re-audited after repair. Matrix repair tasks reuse cross-tree sources first, batch-inspect complete caches, refresh shallow caches in place, and search only when the saved evidence cannot close the gap.

When a matrix issue already contains the missing years, completion suppresses the redundant year-only repair task for that node. This keeps one focused repair objective instead of spending separate agent runs on the same table.

## Freshness and negative findings

Time-sensitive coverage uses `KnowledgeNode.metadata.publishedAt`. Sources without dates produce `unknown_source_freshness`; sources outside the configured window produce `stale_research_requirement`. Strict mode blocks unknown freshness, while balanced mode blocks known-stale evidence for a must requirement and warns when metadata is missing.

A directly evidenced refutation is a valid result: a `contradicted` hypothesis can proceed to the report. Mixed support and contradiction must use `partially_supported` and cite both sides. Inconsistent status/evidence combinations are blocked as `evidence_status_inconsistent`.
