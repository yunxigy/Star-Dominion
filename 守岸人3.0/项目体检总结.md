# 守岸人 3.0 项目体检总结

本文档基于当前项目结构、后端路由、前端交互与配置文件的静态检查整理。

---

## 一、项目现状概览

守岸人 3.0 核心功能已完整：

- ✅ 用户注册、登录、JWT 认证
- ✅ 角色卡管理、头像上传
- ✅ 单角色文本/语音对话、异步 TTS
- ✅ 群聊模式，多角色共同回复
- ✅ 语音陪伴 WebSocket
- ✅ 互动剧情、选项、分支、收藏、评分、分享
- ✅ 记忆系统、Lorebook
- ✅ 角色羁绊系统
- ✅ 管理后台（用户管理、内容审核、系统监控、数据备份）

## 二、仍需处理的问题

### 1. 密码哈希强度不足

当前使用固定盐 SHA256：[`server/middleware/auth.py`](server/middleware/auth.py:27)

```python
salt = "shouanren2024"
return hashlib.sha256((salt + password).encode()).hexdigest()
```

影响：

- 固定盐无法抵御彩虹表或批量破解。
- SHA256 是高速哈希，不适合密码存储。
- 注册、重置密码、默认管理员创建仍写入该格式。
- 登录时所谓“迁移”也只是重新生成同一种弱哈希：[`server/routers/auth.py`](server/routers/auth.py:104)

建议：

- 使用 `bcrypt` 或 `argon2`。
- 首次启动时强制修改默认管理员密码。
- 对旧密码哈希做一次性迁移，不能迁移到同一种弱算法。

---

### 2. JWT 默认密钥太弱

当前默认密钥是固定字符串：[`server/middleware/auth.py`](server/middleware/auth.py:17)

```python
SECRET_KEY = os.getenv("JWT_SECRET", "shouanren-2.0-secret-key-change-in-production")
```

影响：

- 如果部署者没有设置环境变量，JWT 可被预测和伪造。
- 生产环境存在越权登录风险。

建议：

- 生产环境必须设置强随机 `JWT_SECRET`。
- 未设置时拒绝启动，而不是使用默认值。
- `start.bat` 已有类似检查，但 Docker/uvicorn 路径也需要统一。

---

### 3. 默认管理员密码固定

默认管理员仍使用固定配置：[`server/main.py`](server/main.py:45)

```python
admin_username = admin_config.get("username", "admin")
admin_password = admin_config.get("password", "admin123")
admin_email = admin_config.get("email", "admin@shouanren.com")
```

影响：

- 新安装环境容易被直接登录后台。
- 如果配置文件被提交或泄露，管理员账号可直接被使用。

建议：

- 首次启动必须要求修改默认密码。
- 支持通过环境变量创建初始管理员。
- 后台管理页面增加“首次登录强制改密”。

---

### 4. API Key 仍以配置文件形式保存

`data/config.yaml` 保存 LLM/TTS 等 API Key，默认配置中也保留 `api_key` 字段：[`server/config.py`](server/config.py:22)

影响：

- 配置文件容易被误提交。
- 备份、截图、分享项目时可能泄露密钥。
- Docker 镜像如果 `COPY . .` 会把密钥打进镜像层。

建议：

- 优先使用环境变量。
- 配置页只展示 `has_key`，不返回真实 key。
- 在 `.gitignore` 和 `.dockerignore` 中明确排除 `data/config.yaml`、`.env`、数据库和音频缓存。

---

### 5. 文件上传缺少安全校验

角色头像、参考音频上传没有大小限制、MIME 校验和 UUID 文件名保护：[`server/routers/characters.py`](server/routers/characters.py:244)

影响：

- 可能上传超大文件占满磁盘。
- 可能上传非图片/非音频文件。
- 固定文件名存在覆盖风险。
- 静态目录 `/avatars`、`/audio` 暴露文件访问路径。

建议：

- 增加最大文件大小限制。
- 增加扩展名和 MIME/文件头校验。
- 使用 UUID 文件名。
- 对音频做格式/采样率校验。
- 对静态资源目录做访问权限控制。

---

### 6. 数据库迁移不够可靠

当前迁移通过 `_ensure_column()` 补字段：[`server/database.py`](server/database.py:85)

影响：

- 只处理新增列，不处理字段类型变化、索引、外键、约束。
- SQLite 对 `ALTER TABLE` 支持有限。
- 手动迁移没有版本号，容易出现环境不一致。
- 新增羁绊表虽然会被 `create_all()` 创建，但旧库中已有相关字段缺失时仍不会被补齐。

建议：

- 引入 Alembic。
- 增加迁移版本表。
- 对 SQLite/PostgreSQL 分别测试迁移脚本。
- 对新增羁绊系统增加专门迁移记录。

---

### 7. CORS 配置过宽

当前允许所有来源且允许携带凭据：[`server/main.py`](server/main.py:183)

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

影响：

- 浏览器会允许任意站点携带本地 token 访问接口。
- 与 `allow_credentials=True` 组合风险更高。

建议：

- 仅允许项目自己的前端来源。
- 本地开发、生产环境分别配置白名单。
- 不长期使用 `allow_origins=["*"]`。

---

### 8. 新增羁绊系统存在集成隐患

`main.py` 已导入并注册 `affinity.router`：[`server/main.py`](server/main.py:178)

```python
from .routers import characters, chat, settings, auth, admin, story, group_chat, voice_chat, lorebook, memory, affinity
app.include_router(affinity.router)
```

但当前没有看到类似其他服务路由的初始化调用：

```python
characters.init_router(...)
chat.init_router(...)
story.init_router(...)
group_chat.init_router(...)
voice_chat.init_router(...)
memory.init_router(...)
```

影响：

- 如果后续 `affinity.init_router()` 需要注入 LLM、TTS、配置或目录，当前不会生效。
- 路由已暴露，但服务依赖可能为空。
- 如果羁绊系统计划影响聊天回复，当前聊天流程还没有调用 [`update_affinity_on_chat()`](server/routers/affinity.py:168)。

建议：

- 如果羁绊系统需要服务，新增 `affinity.init_router(llm_service)` 并写入 [`server/main.py`](server/main.py:197) 附近。
- 在单聊成功后调用 [`update_affinity_on_chat()`](server/routers/affinity.py:168)，例如 [`server/routers/chat.py`](server/routers/chat.py:393) 保存历史之后。
- 在群聊成功后也可为被提及或发言角色增加羁绊。
- 羁绊变更应记录 `source`、`reason`、`created_at`，方便前端解释“为什么涨/降好感”。

---

### 9. 羁绊等级字段语义混乱

当前模型中：

- `level` 注释为“羁绊等级 0-100”：[`server/models/affinity.py`](server/models/affinity.py:16)
- `affinity_points` 是亲密度积分：[`server/models/affinity.py`](server/models/affinity.py:17)
- `to_dict()` 又把 `level` 传给 [`get_level_name()`](server/models/affinity.py:74)

```python
"level": self.level,
"level_name": get_level_name(self.level),
```

影响：

- `level` 到底是等级编号还是积分，语义不清晰。
- 增加亲密度时更新的是 `affinity_points`，但返回的 `level_name` 来自 `level`，可能不会随积分变化。
- 前端容易展示错误等级名。

建议：

- 保留 `affinity_points` 表示积分。
- 新增或明确 `level` 为等级编号，例如 0-5。
- 新增 `next_level`、`next_level_points`、`progress_percent` 字段。
- `level_name` 应基于 `affinity_points` 或明确的等级编号计算。

---

### 10. 羁绊增加接口缺少权限和参数校验

`add-points` 是公开 POST 路由：[`server/routers/affinity.py`](server/routers/affinity.py:64)

```python
@router.post("/characters/{character_id}/add-points")
async def add_affinity_points(...):
```

影响：

- 登录用户可给自己与任意角色无限刷亲密度。
- `points` 可为负数，能刷低或制造异常数据。
- 没有验证角色是否存在、是否可见。
- 没有频率限制，容易刷库。

建议：

- 若只用于内部调用，应改为内部函数，不暴露 HTTP 接口。
- 若保留接口，应限制 `points` 范围，例如 1-10。
- 增加冷却时间和每日上限。
- 校验角色归属和可见性。
- 增加事件来源白名单：`chat`、`voice`、`gift`、`story`。

---

### 11. 用户偏好缺少内容长度和类型限制

偏好创建只校验 `content: str`：[`server/routers/affinity.py`](server/routers/affinity.py:15)

影响：

- 可写入超长文本，污染上下文。
- 没有校验 `importance` 范围。
- 没有校验 `preference_type` 枚举。
- 全局偏好和角色偏好缺少数量上限。

建议：

- 使用 `Field(..., min_length=1, max_length=500)`。
- `importance` 限制为 1-10。
- `preference_type` 使用枚举。
- 每个角色/全局偏好设置上限，例如 20 条。
- 注入聊天上下文时只取最高优先级的若干条。

---

### 12. 聊天流程尚未把记忆、羁绊、偏好真正串联

当前单聊会加载 Lorebook 和记忆：[`server/routers/chat.py`](server/routers/chat.py:359)

但还没有看到：

- 羁绊等级影响角色语气。
- 用户偏好注入系统提示词。
- 羁绊事件触发特殊对话或剧情。
- 群聊中角色关系影响发言顺序。

影响：

- 羁绊系统目前更偏统计记录，内容体验增强有限。

建议：

- 在 `build_system_prompt()` 前加入：
  - 当前羁绊等级名。
  - 最近羁绊事件。
  - 用户对该角色的偏好。
  - 用户全局偏好。
- 让高等级角色解锁更多称呼、语气、记忆引用和专属剧情。
- 群聊中加入“关系网”：角色之间也有羁绊，影响互动。

---

### 13. 聊天接口仍会复用同一角色的默认会话

`_get_or_create_session()` 会按用户和角色复用会话：[`server/routers/chat.py`](server/routers/chat.py:566)

影响：

- 前端切换角色时会进入该角色最近会话。
- 用户想“新开一段聊天”时缺少明确入口。
- 羁绊增长、记忆更新会集中在默认会话上。

建议：

- 增加“新聊天”按钮。
- `/api/chat` 支持 `new_session=1`。
- 角色卡片显示最近会话摘要。
- 会话列表支持重命名、归档、删除。

---

### 14. 异步任务复用数据库 Session 有稳定性风险

聊天中会创建后台任务并传入当前 `db`：[`server/routers/chat.py`](server/routers/chat.py:404)

```python
asyncio.create_task(
    extract_memories(current_user.id, character.id, recent_history, db)
)
```

影响：

- 请求结束后 Session 可能被关闭，后台任务继续使用时可能出错。
- 多个任务并发读写同一 Session 不安全。
- 进程重启后 TTS/记忆任务状态丢失。

建议：

- 后台任务内重新创建 Session。
- 使用任务队列或轻量持久化表。
- TTS 任务增加数据库状态表。
- 对 `asyncio.create_task()` 增加异常捕获和日志。

---

### 15. TTS 任务仍只在内存中保存

异步 TTS 状态保存在全局字典：[`server/routers/chat.py`](server/routers/chat.py:437)

影响：

- 重启后任务状态丢失。
- 多进程/多 worker 部署时状态不一致。
- 无法长期查询历史音频。

建议：

- 将 TTS 任务状态写入数据库。
- 音频文件加用户隔离路径。
- 增加任务超时和失败重试。
- 前端轮询接口继续复用现有设计即可。

---

### 16. 前端仍存在 XSS 风险

角色列表中把角色 ID 放进 `onclick` 属性：[`frontend/js/app.js`](frontend/js/app.js:39)

```javascript
onclick="selectCharacter('${escapeAttr(c.id)}')"
```

`index.html` 中也有多处内联事件：[`frontend/index.html`](frontend/index.html:19)

影响：

- 如果角色 ID、名称、描述来自用户输入，仍有注入风险。
- 内联 `onclick`、`onerror` 不利于 CSP。
- `renderCharacterList()` 中大量 `innerHTML` 增加维护风险。

建议：

- 使用 `createElement()` 和 `textContent` 构建角色卡片。
- 移除内联 `onclick`，统一用 `addEventListener()`。
- 对头像 URL 做白名单或转义。
- 后续可加 CSP。

---

### 17. API 请求重试仍可能重复提交

虽然 `api.js` 增加了刷新并发保护：[`frontend/js/api.js`](frontend/js/api.js:6)

但重试逻辑仍可能重复提交非幂等请求。

影响：

- POST/PUT 请求在 token 过期后可能重复执行。
- FormData 请求重试时，如果浏览器已消费流，也可能失败。
- 错误提示较笼统，不利于定位后端真实错误。

建议：

- 对 POST/PUT/DELETE 增加 `retry: false` 或提示用户重试。
- 请求体不要原地修改，使用 `requestBody` 副本。
- 统一错误格式解析。
- 对表单上传增加超时提示。

---

### 18. 前端认证状态可能刷新后丢失用户信息

`Auth.refreshToken()` 调用 [`setAuth(data.access_token, data.refresh_token, null)`](frontend/js/auth.js:109)

影响：

- 如果后端 refresh 不再返回完整用户对象，前端已有用户信息会保留。
- 如果登录时没有保存用户对象，刷新后页面可能无法显示用户名。
- `setAuth()` 不会删除旧用户信息，容易残留过期角色或权限。

建议：

- refresh 成功后请求 `/api/auth/me`，用最新用户信息更新本地状态。
- 登出时清理所有认证相关缓存。
- 管理员权限以服务端校验为准，前端只用于显示入口。

## 三、功能扩展建议

### 1. 内容生态：角色市场与模板库

当前项目已有角色卡、剧情、群聊，但内容还偏少。建议增加：

- 官方角色包（鸣潮角色、日常陪伴、学习助手等）
- 剧情模板（同人支线、末日求生、校园怪谈等）
- 群聊剧本（茶会闲聊、冒险小队、侦探推理等）
- 支持导入/导出角色包 JSON
- 支持“一键安装官方内容包”
- 角色包版本号、作者、标签、预览图

---

### 2. 羁绊系统深化

当前羁绊系统已具备基础模型和路由，但还可以继续丰富：

- 羁绊等级解锁专属称呼、语气、开场白。
- 羁绊事件日志：聊天、语音、送礼、剧情选择都会留下记录。
- 角色礼物系统：生日、节日、纪念日触发特殊对话。
- 角色偏好系统：每个角色喜欢/讨厌的话题、食物、称呼。
- 角色关系网：群聊中角色之间也有羁绊，影响互动。
- 羁绊排行榜：展示最常聊天、最亲密、最近互动的角色。
- 羁绊成就：首次满级、连续聊天、解锁隐藏剧情。

---

### 3. 语音陪伴增强

当前已有 WebSocket、STT、TTS，建议增加：

- 支持真正流式 TTS 播放
- 支持打断 TTS 播放
- 支持通话模式（低延迟/高音质/省电）
- 支持语音情绪（开心/安慰/撒娇/认真/睡前）
- 支持角色自定义音色包
- 支持语音消息转文字后保留原音频
- 支持背景白噪音/雨声/海边声景

---

### 4. 世界书增强

当前 Lorebook 支持关键词触发，建议增加：

- 世界书分类（角色设定、地点、事件、术语）
- 触发方式（关键词、正则、语义相似度）
- 注入策略（始终注入、仅当前剧情、仅群聊）
- 冲突检测（重复关键词、内容过长）
- 世界书预览：显示当前会注入哪些条目
- 语义检索：使用 embedding 做相似内容召回

---

### 5. 剧情模式增强

当前剧情模式已有分支和选项，建议增加：

- 剧情地图（分支节点可视化、可回滚）
- 剧情状态变量（生命值、理智值、好感度、背包）
- 剧情成就（首次探索、隐藏结局、全选项收集）
- 剧情导入导出（JSON、YAML）
- 剧情评分与评论
- 剧情角色羁绊联动：不同角色好感度解锁不同支线
- 剧情存档快照：可随时保存当前分支状态

---

### 6. 群聊模式增强

当前群聊已有成员、发言顺序和触发机制，建议增加：

- 群聊房间主题和公告
- 角色发言冷却和最大发言人数
- 角色关系影响抢话概率
- 群聊剧本：茶会、会议、冒险、推理、课堂
- 群聊投票/选项
- 群聊摘要：自动生成今日聊天纪要
- 群聊成员推荐：根据角色设定推荐可加入角色

---

### 7. 用户个性化增强

建议增加更完整的用户画像：

- 用户昵称、头像、生日、时区
- 用户偏好（称呼、语气、内容尺度、话题兴趣）
- 用户纪念日（生日、入坑日、重要事件）
- 每日签到和连续聊天记录
- 用户专属记忆摘要
- 用户数据导出/删除

---

### 8. 前端工程化

当前前端是原生 JS，建议：

- 如果规模继续扩大，可迁移到 Vue/React
- 如果保持原生 JS，建议按功能拆分模块
- 增加全局错误处理、loading 状态
- 增加移动端适配
- 增加 PWA（离线缓存、桌面图标）
- 移除内联事件，降低 XSS 风险
- 增加无障碍支持和键盘快捷键

---

### 9. 运维和产品化

建议增加：

- Docker Compose 一键启动
- 环境变量示例 `.env.example`
- 数据备份和恢复脚本
- 日志轮转
- 系统监控面板
- 模型后端健康检查
- 使用量统计（Token、TTS 分钟数、STT 次数）
- 管理员审计日志

## 四、推荐落地路线
