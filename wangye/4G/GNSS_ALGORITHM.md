# GNSS位移质量控制与抗差自适应滤波

当前算法版本为 `robust-adaptive-position-kf-v1`。各轴采用单一位置状态及随机游走模型，不估计速度。GNSS计算位于后端，网页读取同一份服务端结果。

GGA检查通过后，将经纬度和椭球高转换为WGS84 ECEF；椭球高为GGA海拔高度与大地水准面差之和。每台设备以连续20个合格RTK固定解的ECEF均值建立固定参考，再将缓存的20个历元按原GNSS时标顺序处理。参考建立前，网页显示准备进度。参考建立后按实际GNSS时间间隔逐点更新。

| 参数 | 当前值 |
|---|---|
| 位置过程方差 | Q = 0.25 Δt mm²，Δt以秒计 |
| 基础测量标准差 | E/N为10 mm，U为20 mm |
| HDOP方差系数 | clip(HDOP², 0.5, 4) |
| Huber阈值 | c = 3 |
| 自适应尺度更新 | β = 0.05，α初值1，限于1～25 |
| 等效测量方差 | Reff = α Rb / w |
| 初始位置方差 | 基础测量方差σ₀² |
| 协方差更新 | Joseph形式 |

校验和缺失或不匹配、字段无效、非RTK固定解均不更新位置滤波。重复或乱序GNSS历元不重复更新，也不刷新有效观测的接收时间。GGA跨午夜按UTC连续处理；长时间中断后结合服务端接收时刻恢复会话。差分龄期保留在输出中，不将其直接等同于定位误差。

质量退化时最多输出10秒位置预测，超时后`filtered_enu_mm`为空并标记`expired`。有效观测间断超过15秒时，重新初始化滤波状态，固定参考点保持不变。较大残差采用降权处理，不再执行恒速模型的连续残差重置。普通页面刷新、切换设备和清除地图轨迹均不改变固定参考。

`/data`和`/ws`中每台设备的`gnss`字段包含当前状态、参考编号、原始及滤波ENU、按GNSS历元组织的历史和质量信息。后端单位为mm，网页换算为cm，并分别显示原始与滤波曲线。地图坐标转换只用于底图显示，不参与位移计算。

默认在`4G.py`旁的`gnss_runtime/`保存各设备的参考、滤波状态和最近300个历元，同时追加原始GGA及处理结果日志。可通过`STM32_GNSS_STATE_DIR`指定持久化目录。服务更新或重启时应保留该目录；损坏的状态文件会明确报错，不会静默建立新零点。调整天线、基准站坐标或监测基准后，应停下对应设备的数据处理，归档原状态并明确建立新的监测会话。

按现有`4G.py`入口运行单个状态计算实例。多个浏览器连接共享结果；不要让多个独立后端进程分别计算同一设备的状态。参数修改和重建参考应对应新的实验或监测记录。

更新网站时需同时更新后端`4G.py`、`gnss_filter.py`，以及前端`Stm32Window.tsx`和`stm32/`中相应类型、解析、地图及位移面板文件。Python依赖列表没有增加第三方科学计算库。
